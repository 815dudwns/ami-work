# 데이터검증관리자 — awms 전송탭 (계기큐 맥 이식) 설계

> 영준님 지시 2026-07-02. 계기큐(폰) awms 등록을 데이터검증관리자(맥)로 이식.
> UI는 추후 수정 예정 → 기능 구현 우선, UI는 최소.

## 역할 재편
- **데이터검증관리자(맥) = 컨트롤러** — 실제 전송 제어의 단일 주체
- **계기큐(폰) = 리모컨 실행 팔 + 모니터** — 맥 명령을 받아 폰 awms 웹뷰로 실제 전송(세션은 폰 것). 맥 작업 상황을 공유받아 표시만.
- 실행은 무조건 맥이 지휘. (맥 직접 전송[세션 이식]은 후순위 최적화 — 지금은 폰 리모컨이 기본이자 확실한 경로)

## 전송탭 (검증관리자 신설)
- **검증탭에서 검증완료(isVerified)된 것만** 전송탭으로 진입
- 전송탭 내부 분리: **[미전송] / [전송완료]** (미전송 = 추가조치 필요분)
- **총 진행 %** + 전송 중 상황 + **실시간 전송 로그** 표시

## 전송 설정 (전송 시작 전 1회)
- 데이터셋(공사)에 등록된 **아이디 여러 개 선택 가능** → 각각 OTP 수동 로그인으로 세션 확보
- **공사번호(차수) 고정 지정** — 조회하면 고정값이므로 저장해뒀다 넣음 (건별 자동조회 폐지)
- **아이디별 시작 봉인번호 설정** (봉인은 계정 전역이라 아이디마다 별개)

## 봉인 처리 (핵심 개선)
- 현재(계기큐): 건마다 `mobMtr8000/getMainList`로 봉인·공사번호 조회 → 느림
- 개선:
  - 시작 봉인번호 + 공사번호를 **미리 설정** → 전송 중 조회 없음
  - **로컬 증분**: 단상 +1, 삼상 +2 (연속: N+1, N+2)
  - 삼상 판별 = 계약종별(CNTR_CLAS_CD) 900+ (계기번호 55/45 폴백) — `awms-saverow.js:112-118` 기존 로직
  - 봉인 페이로드: `CSL_METR_TRML_SEAL_NO`(+ 삼상이면 `_NO2`), `CSL_METR_TRML_SEAL_KND_NQNT`(단상1/삼상2) — `awms-saverow.js:150-153`
  - **마지막 건 끝나면 최종 봉인번호를 `mobMtr8000/saveRow`로 서버에 1회 저장** (건별 저장 폐지)
- **봉인번호 DB 저장**: 전송 성공 시 계기 레코드(`workStatus/jongno/{주소}/replacement_list/{구계기}`)에 봉인번호(단상 1 / 삼상 2) 기록
  - 목적: ①검증관리자 상세에서 봉인번호 조회 ②한전 제출용 **차수별 준공 리스트(김창숙 엑셀)에 봉인번호 매칭/채우기**
  - 기존 `awms_synced`/`awms_response` 기록 자리(`queue.js:669 markSynced`)에 봉인번호 필드 추가

## 등록 플로우 (기존 계기큐 로직 재사용)
`awms-saverow.js:621 registerReplacement()` 순서 유지:
1. 봉인/공사번호 = **미리 설정값 사용**(조회 생략)
2. 고객조회(selectCustomerInfo) — 계약종별/전력 필요분만
3. 철거 saveRow(mobMtr5000) → consTgtSeqno
4. getDetail(mobMtr1000, cha 대기재시도)
5. 신설 saveRow(mobMtr4000) — 봉인번호 주입 + WORK_STEP=25
6. 완료(28): getDetail 재조회 + 시공17키 + 신설사진 재전송
7. 성공 시 봉인번호 DB 저장, 봉인 로컬 +1/+2

## 완료판정·중복방지 (기존)
- awms `getMainList?workStep=25,28` + ami-work `awmsDoneMeters.json` 영구누적 (`queue.js`)
- 이미 완료(28)면 전송탭 [전송완료]로, 실패/미등록은 [미전송]
