# 관리자 검증 도구 — 디자인 지침 (admin-validate)

> **목적**: 앞으로 이 페이지에 기능이 추가될 때 디자인이 흔들리지 않도록 하는 단일 기준.
> **단일 소스**: `css/clay.css` (표면·그림자·반경·메인색 토큰). 여기에 변수를 새로 만들지 말 것.
> **리빙 샘플**: `관리자 검증 - 리디자인 제안.html` + `js/admin-demo.js` — 아래 모든 패턴이 실제로 동작합니다. 새 컴포넌트는 거기서 먼저 만들어 보세요.

---

## 0. 절대 규칙

1. **clay 토큰만.** 색은 `--surface/--bg/--bg-deep/--ink/--ink-2/--ink-3/--mint*`, 그림자는 `--clay/--clay-sm/--clay-inset/--clay-inset-sm/--clay-mint`, 반경은 `--radius/--radius-sm/--radius-pill`. **`--line`·`--accent` 같은 비-clay 변수는 만들지 마세요(만들면 깨집니다).**
2. **메인색 = 블루(슬레이트).** clay의 `--mint*` 패밀리를 블루로 오버라이드해서 씁니다(§2). 버튼·탭·활성·도넛·추이·주지표가 전부 이 한 색을 따라갑니다.
3. **데이터 색은 페이지 로컬 팔레트(`--a-*`)로.** clay에는 진한 상태 텍스트색이 없으므로, 이 도구 전용 분석 팔레트를 **이 페이지의 `<style> :root`** 에만 정의합니다(clay.css 오염 금지). §3.
4. **외곽선 대신 그림자.** `border: 1px solid` 금지. 입체는 볼록(`--clay-sm`)/음각(`--clay-inset-sm`)으로.
5. **폰트 `var(--font)`(Pretendard), 이모지·아이콘폰트 없음.** 상태는 색 배지/점으로.
6. **숫자는 `font-variant-numeric: tabular-nums`.** 계기번호·검침값·통계 전부.
7. **데스크톱 전용.** 모바일 대응 불필요(좁아질 때 깨지지만 않게 `@media`로 최소 방어).
8. **★다크모드 필수.** clay.css가 `[data-theme="dark"]`·OS 자동추종 둘 다 지원함. 새로 넣는 색은 **절대 진한 hex를 박지 말 것** — soft 배경 위 텍스트는 반드시 다크 대응 `--a-*`(§3) 사용. 라이트만 보고 끝내지 말고 **다크로 토글해 글자가 보이는지 확인**(§3 이유).

## 2. 메인색 (블루) — clay 토큰 오버라이드

이 도구는 clay 기본(세이지)이 아니라 **블루(슬레이트)** 를 메인으로 씁니다. 페이지 `:root` 또는 JS로 `--mint*` 패밀리만 덮어씁니다:

```css
:root {
  --mint:        #9fb6dd;  /* 소프트 블루 (버튼/칩 배경 톤) */
  --mint-l:      #b8cae8;  /* 밝은쪽 (버튼 그라데이션 상단) */
  --mint-ink:    #4f74b0;
  --mint-strong: #42659c;  /* 텍스트 강조 */
  --mint-deep:   #27406e;  /* 버튼 라벨 딥 */
  --mint-soft:   #dde6f4;  /* 옅은 칩 배경 */
  --mint-glow:   rgba(90,140,220,.5);
}
```

> 데모에는 헤더에 **메인색 스위처**(틸/슬레이트/테라코타/에메랄드)가 있어 라이브로 바꿔볼 수 있습니다. 운영 반영 시엔 **슬레이트 고정**입니다. 차트 주색(`CHART_PRIMARY`)도 이 값으로 맞춰 통일합니다.

## 3. 데이터 팔레트 (페이지 로컬 `--a-*`) — ★다크모드 안전 필수

clay 상태색(`--green/--amber/--rose`…)은 파스텔이라 "soft 배경 위 진한 텍스트"가 없습니다. 그래서 실제 파일은 `#92400e`·`#1e40af`·`#b91c1c` 같은 **진한 hex를 직접 박아** 썼는데 — 이게 **다크모드를 깨뜨립니다.** 다크에서 `--amber-soft`는 어두운 갈색(`#463922`)이 되는데 그 위에 어두운 amber 텍스트(`#92400e`)를 올리면 **글자가 안 보입니다.**

해결: 차트·배지 텍스트색을 **라이트/다크 둘 다 정의한 페이지 로컬 `--a-*` 토큰**으로 통일합니다. soft 배경도 다크 틴트로 같이 정의. **clay.css는 건드리지 않고**, 이 도구 페이지 `<style>`에만 둡니다.

```css
/* 라이트 (기본) */
:root {
  --a-green:#2f7d54; --a-green-soft:#d2e9da;   /* 완료 · 통과 · 좋음 */
  --a-teal:#2a8a8a;  --a-teal-soft:#cfe8e6;    /* 단상 */
  --a-blue:#3f74c0;  --a-blue-soft:#d3e2f4;    /* 보조 · 확인완료 보조 */
  --a-violet:#7059b0;--a-violet-soft:#e0d8f1;  /* 삼상 · 스왑 */
  --a-amber:#9a6a1e; --a-amber-soft:#f3e1bf;   /* 추가 · 잔여 · 확인필요 */
  --a-rose:#b3433f;  --a-rose-soft:#f3d2d2;    /* 오류 · 실패 · 불가 · 정합성 */
  --a-remain:#a89f8e;
}
/* 다크 강제 */
[data-theme="dark"], .theme-dark {
  --a-green:#7fd6a4; --a-green-soft:#244236;
  --a-teal:#74cfcf;  --a-teal-soft:#1f4040;
  --a-blue:#8fb8ec;  --a-blue-soft:#23344a;
  --a-violet:#bba8e8;--a-violet-soft:#2f2950;
  --a-amber:#e8c074; --a-amber-soft:#463922;
  --a-rose:#ec9b98;  --a-rose-soft:#46282a;
  --a-remain:#6f6a5e;
}
/* OS 다크 자동 추종 (사용자가 라이트/다크 강제 안 한 경우) — clay.css와 동일 패턴 */
@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]):not([data-theme="dark"]) {
    --a-green:#7fd6a4; --a-green-soft:#244236;
    --a-teal:#74cfcf;  --a-teal-soft:#1f4040;
    --a-blue:#8fb8ec;  --a-blue-soft:#23344a;
    --a-violet:#bba8e8;--a-violet-soft:#2f2950;
    --a-amber:#e8c074; --a-amber-soft:#463922;
    --a-rose:#ec9b98;  --a-rose-soft:#46282a;
    --a-remain:#6f6a5e;
  }
}
```

**색 의미 고정표 (바꾸지 말 것):**

| 의미 | 색 |
|---|---|
| 완료 / 자동통과 / 진행 양호 | `--a-green` |
| 단상 | `--a-teal` |
| 삼상 | `--a-violet` |
| 추가계기 / 잔여 / 확인필요 / 경고 | `--a-amber` |
| 오류 / 실패 / 불가 / 정합성 | `--a-rose` |
| 확인완료(사람 판정) / 주지표(도넛·추이·진행률) | **메인색**(`--mint*`) |
| 스왑 의심 | `--a-violet` |

> 원칙: **주지표(완료율·추이·진행 바)는 메인색**, **카테고리(단상/삼상/추가)는 메인색과 겹치지 않는 고정색**. 그래서 단상=틸·삼상=보라(블루 메인과 분리).

### 3-1. 실제 파일 hardcoded hex → 토큰 교체 매핑표 (★클로드코드 적용용)

`admin-validate.html`에서 아래 hex를 전부 토큰으로 바꾸면 다크모드가 정상화됩니다. CSS·인라인 style·JS 템플릿 문자열 **모두** 대상.

| 박혀있는 hex | 쓰임 | 교체 |
|---|---|---|
| `#92400e` `#7a5200` `#b45309` | 진한 amber 텍스트 (확인필요/추가/경고) | `var(--a-amber)` |
| `#fef3c7` `#fffbeb` | 옅은 amber 배경 (스왑/게이트 배너) | `var(--a-amber-soft)` |
| `#1e40af` `#3b82f6` `#1d4ed8` | 진한·중간 blue 텍스트 (확인완료/스피너) | `var(--a-blue)` |
| `#b91c1c` `#7f1d1d` | 진한 red 텍스트 (오류/실패/멈춤) | `var(--a-rose)` |
| `rgba(185,28,28,.15)` 등 | 정합성 배지 배경/보더 | `var(--a-rose-soft)` |
| `#f59e0b` → `#fbbf24` 그라데이션 | 진행 막대 (running) | `linear-gradient(90deg, var(--a-amber), var(--a-amber))` 또는 메인색 |
| `#000` (사진 배경) | LCD/사진 레터박스 | 그대로 OK (두 모드 공통) |

> 배지 클래스(`.sb-need/.st-need/.ms-pending` 등)는 이미 `--amber-soft` 배경을 쓰되 **텍스트만 hex**입니다 → 텍스트 색만 `var(--a-amber)` 등으로 바꾸면 끝. 배경은 clay soft 토큰이 이미 다크 대응됨.

## 4. 배지 (상태 표시)

soft 배경 + 동색 진한 텍스트 + `--clay-sm`. 알약형. 작게.

```css
.st, .ms, .sbadge { border-radius: var(--radius-pill); font-weight: 800; box-shadow: var(--clay-sm); white-space: nowrap; }
.st, .ms { font-size: 11px; padding: 4px 11px; }
.sbadge  { font-size: 12px; padding: 6px 13px; }     /* 요약 배지 */
```

검증상태(`.st-*`): 자동통과 `--a-green` / 확인필요 `--a-amber` / OCR미판독·사진없음 `--gray` / 확인완료 **`--mint-soft`+`--mint-strong`** / 스왑의심 `--a-violet`.
완료상태(`.ms-*`): 완료 `--a-green` / 미완료 `--a-amber` / 보류 `--a-violet` / 실패 `--a-rose`.

```html
<span class="st st-need">확인필요</span>
<span class="st st-swap">스왑 의심</span>
<span class="ms ms-complete">완료</span>
```

**새 상태가 생기면**: 위 의미 고정표에서 가장 가까운 색을 골라 `*-soft` 배경 + 진한 텍스트. 새 색을 발명하지 마세요.

## 5. 표

음각 래퍼 안에 표. 헤더는 라벨 톤, 행 hover는 웜그레이 틴트, 클릭행은 `cursor:pointer`.

```css
.vtable-wrap { background: var(--bg-deep); box-shadow: var(--clay-inset-sm); border-radius: var(--radius-sm); overflow: hidden; }
.vtable th { font-size:11px; font-weight:800; color: var(--ink-3); text-transform: uppercase; }
.vtable td { border-top: 1px solid rgba(165,158,144,0.16); }   /* 외곽선 X, 옅은 구분선만 */
.vrow:hover td { background: rgba(120,113,100,0.08); }
```

- 계기번호는 타입 자리(3~4번째) 강조: `<span class="mid-type">` → `color: var(--mint-strong)`.
- 값 셀은 `tabular-nums`, 비고 등 텍스트는 좌측정렬 + ellipsis.

## 6. 검증 상세 모달 (핵심)

구조: **오버레이(웜블랙 딤) → 박스(--surface, --clay) → 요약 → 섹션들**.

```
.detail-overlay (rgba(44,42,39,.5), 스크롤 가능, 상단정렬)
  .detail-box (max-width 960, --clay)
    .detail-header  (제목 + 닫기 버튼)
    .event-summary  (음각 그리드: 순번/고객/일시/철거·신설번호/제조년월/완료상태/비고)
    .detail-sections
      .vblock           ← 섹션 = 음각 패널 (현장정보 / 철거 / 신설 / 검침값)
        .vblock-title   (하단 옅은 구분선)
        .vblock-item    ← 판정 1건
          .vblock-head  (이름 + 상태배지)
          .vblock-body  (grid 200px + 1fr)
            .vphoto-wrap  ← 사진 / .no-photo / .no-photo.same(동일파일)
            .vblock-right
              .cmp-grid   ← 작업자입력 vs OCR (음각 셀 2개)
              .match-badge(일치/불일치/미판독)
              .cand-row   ← 후보 버튼들(클릭=입력칸 채움, 선택시 메인색 볼록)
              .vform      ← 입력 + 불가사유 + [판정저장][미리보기][확정반영]
```

**경고 블록** — 정합성/스왑은 섹션을 통째로 색칠:
```css
.alert-block.consistency { background: var(--a-rose-soft); box-shadow: var(--clay-sm); }
.alert-block.swap        { background: var(--a-amber-soft); box-shadow: var(--clay-sm); }
```
스왑은 `.swap-pair`(이 칸 ⇄ 상대) 두 카드에 철거사진 나란히 + [맞바꾸기] 메인 버튼.

**판정 폼 버튼 규칙**:
- `판정 저장` = `.cbtn.cbtn-primary.cbtn-sm` (메인색 볼록)
- `미리보기` = `.cbtn.cbtn-sm` (기본 볼록)
- `확정 반영` = 처음엔 `disabled`(opacity .45) → 미리보기 성공 후 활성. 파괴적 동작은 항상 미리보기 게이트.

**모달 작업 시 주의**: 사진은 클릭 시 원본 새 탭(`onclick="window.open(this.src)"`). 사진 없으면 `.no-photo`, 철거사진과 동일 파일이면 `.no-photo.same`(중복 이미지 표시 안 함).

## 7. 통합 날짜 컨트롤

검증·통계·이력이 **하나의 날짜를 공유**. 매번 달력 팝업을 열지 않아도 되게 설계.

구성:
- `‹ [날짜 (요일) · 작업N건] ›` — 화살표로 하루 이동, 가운데 클릭하면 팝오버 달력
- 프리셋: `오늘 / 어제 / 최근 작업일`
- **작업일 칩 스트립** (`.work-chips`) — 작업 있는 날만 `MM/DD·요일·건수`로. 핵심 UX: 달력에서 찾지 말고 바로 점프.
- 팝오버 달력(`.cal-pop`) — 작업일에 점(`.cal-dot`), 선택일 메인색.

```css
.date-display { background: var(--bg-deep); box-shadow: var(--clay-inset-sm); border-radius: var(--radius-pill); }
.work-chip { background: var(--surface); box-shadow: var(--clay-sm); }       /* 볼록 칩 */
.work-chip.active { background: linear-gradient(145deg,var(--mint-l),var(--mint)); box-shadow: var(--clay-mint); }
```

> 구현은 `js/admin-demo.js`의 `setDate / shiftDate / presetDate / renderWorkChips / renderCal`. 실제 앱에선 air-datepicker 대신 이 컨트롤을 쓰거나, 최소한 **작업일 칩 스트립**만이라도 얹으면 체감이 크게 좋아집니다.

## 8. 차트 — clay 질감 규칙

차트도 평면이 아니라 clay로. **트랙은 음각, 값은 볼록.**

- **도넛(완료율)**: 원형 음각 웰(`.donut-wrap { box-shadow: var(--clay-inset-sm) }`) 안에, 링은 메인색 그라데이션(`lighten→darken`) + `filter: drop-shadow(...)`.
- **막대 추이**: 차트 영역 자체를 음각 패널(`.trend-host { background: var(--bg-deep); box-shadow: var(--clay-inset-sm) }`). 막대는 위가 밝은 세로 그라데이션 + `drop-shadow`. **Y축 그리드·값 라벨·X 날짜축 필수**(이전엔 라벨이 없어 안 읽혔음). 누적선은 `--a-amber`.
- **진행/위상/권역 바**: 트랙 `--bg-deep`+`--clay-inset-sm`(음각), 채움은 위쪽 흰 하이라이트(`linear-gradient(180deg, rgba(255,255,255,.34), transparent 58%), <색>`).
- **권역 진행률 색**: ≥85% 초록 / ≥60% 메인블루 / 그 외 앰버 (진행 semantic).

```js
// clay 채움 헬퍼 (admin-demo.js)
function clayFill(c){ return `linear-gradient(180deg, rgba(255,255,255,.36), rgba(255,255,255,0) 56%), ${c}`; }
```

> SVG 막대/링은 `fill`/`stroke`에 `<linearGradient>` + CSS `filter: drop-shadow(1px 2px 2px rgba(90,84,74,.34))`로 솟은 느낌. 그림자색은 따뜻한 웜그레이로(메인색 안 탐).

## 9. 신규 기능 추가 체크리스트

새 화면/위젯을 붙이기 전:

- [ ] 새 색을 hex로 박지 않았는가? → clay 토큰 또는 `--a-*` 의미색 사용
- [ ] **다크모드로 토글해서 글자·배지가 다 보이는가?** (진한 hex 텍스트면 다크에서 사라짐 — `--a-*`로 교체)
- [ ] 그림자를 `--clay*` 로 줬는가? `border` 안 썼는가?
- [ ] 주지표는 메인색, 카테고리는 고정 의미색을 썼는가? (겹치면 분리)
- [ ] 배지는 `soft 배경 + 진한 동색 텍스트 + clay-sm` 인가?
- [ ] 숫자에 `tabular-nums` 줬는가?
- [ ] 컨테이너는 볼록(`--clay-sm`), 입력/트랙/표래퍼는 음각(`--clay-inset-sm`)인가?
- [ ] 파괴적 동작(DB 반영/스왑/되돌리기)에 미리보기·확인 게이트가 있는가?
- [ ] 날짜가 필요하면 **통합 날짜 컨트롤**을 재사용했는가? (새 날짜 입력 또 만들지 말 것)
- [ ] 리빙 샘플(`관리자 검증 - 리디자인 제안.html`)에 먼저 그려보고 확인했는가?

## 10. 빠른 참조 — 토큰/클래스

**그림자**: `--clay`(큰 볼록) · `--clay-sm`(작은 볼록) · `--clay-inset-sm`(음각) · `--clay-mint`(메인 버튼) · `--focus-glow`(포커스 링)
**반경**: `--radius`(카드 22) · `--radius-sm`(14) · `--radius-pill`(999)
**버튼**: `.cbtn` 기본 / `.cbtn.cbtn-primary` 메인 / `.cbtn-sm`·`.cbtn-xs` 크기 / `disabled`는 게이트
**세그**: `.cseg > button(.active)` — 음각 트랙 위 활성만 메인 볼록
**배지**: `.st-*`(검증) · `.ms-*`(완료) · `.sbadge .sb-*`(요약) · `.match-badge .mc-*`(대조)
**모달**: `.detail-overlay/.detail-box/.event-summary/.vblock/.vblock-item/.cmp-grid/.cand-btn/.vform`
**차트**: `.donut/.trend-host/.region-track/.hbar/.progress` (전부 음각 트랙 + 볼록/그라데이션 채움)
**날짜**: `.date-control/.work-chips/.cal-pop`

> 변경 로그·핸드오프 CSS는 색 확정 후 별도 전달. 차트·도넛·작업일칩·통합날짜는 CSS만으로 안 되고 작은 렌더 JS(`renderStats/renderTrend/_initDatePicker` 대체)도 같이 필요 — 드롭인 스니펫으로 제공 예정.
