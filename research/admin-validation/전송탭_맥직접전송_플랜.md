## 0. 목표 플로우 (영준님 확정 2026-07-17)

```
지도앱(종로맵)에서 작업 완료
  → [P0] 백엔드가 완료 감지 → 자동 검증 실행 (포털 안 열어도)
  → 검증 통과건 = 전송탭 [미전송] 목록에 자동 등장 (기존 isVerified 로직 그대로)
  → [P1] 전송탭 [로그인] — 맥 백엔드가 awms 로그인, OTP만 폰 릴레이 (밖에서도 동작)
  → [P2] 전송 실행 — 맥이 awms mob/mtr 직접 호출 (폰 불필요)
        철거(5000) → getDetail 재시도 → 신설(4000, 25) → 완료(28)+사진재전송  ★28까지 자동
  → [P3] 배치 끝나면 계정별 최종봉인 서버저장 (+1)
  → [P4] 사후검증 (옵션 토글) — 올린 건 전체 awms 재조회 → **필드 대조까지**
  → Firebase awms_synced 마킹 → 전송완료 컬럼 → 큐정리 (기존 그대로)
```

결정사항:
- 완료 단계 = **28까지 자동** (검증완료건만 전송하므로. ★28은 되돌리기 불가)
- 사후검증 = **필드 대조까지** (건별 getDetail로 신설번호·봉인·지침·제조월 대조), 토글로 on/off
- 폰 연결 = **무선 필수** (현장에서 사용). USB 전제 금지.

목표: 지도앱에서 완료하면 포털 안 열어도 자동 검증.

구현: 백엔드(8765, launchd 상시)에 **워처 스레드** 추가 — **완료(2026-07-17)**
- **근무시간(08~20시 KST) 내 1시간 1회** 오늘 날짜 검증 실행 (영준님: 60초는 낭비). `_autovalidate_loop` 스레드, `_RUNNING_JOB` 게이트 준수(수동검증·전송잡과 충돌 안 함), config `auto_validate_watch=True`인 dataset만. 토글 API `/transmit/auto-validate` GET/POST.
- 감지 시 기존 검증 파이프라인 그대로 실행 (포털 자동토글과 동일 규칙 — 재과금 가드: 계기단위 1회, human/human_skip 보존 [[daily_cycle_human_status_preserve]])

- 백엔드 설정으로 on/off (`transmit_config.json`에 `auto_validate_watch: true`)

리스크: OCR 백엔드(맥 GPU) 동시실행 충돌 → 기존 잡 게이트(`_RUNNING_JOB`) 통과 후 실행, 검증 잡 돌고 있으면 다음 주기로 미룸.

## P1. 로그인 툴 — 아미큐와 동일: 계기팀 세션 가져오기 (영준님 확정 2026-07-17)

아미큐(통신팀)가 폰 로그인 세션을 맥으로 가져오는 것과 **똑같이, 계기팀 세션만 가져온다**.
- 폰 계기큐에서 awms 로그인(OTP 포함, 기존 `/transmit/login` 자동입력 재사용 가능)
- 세션쿠키(JSESSIONID/rememberedId/XSRF) 추출 → 맥 `SESSION` 보관:
  - **pull (USB)**: adb CDP `Network.getAllCookies` — cst-input `pull_session()` 그대로, 대상만 계기큐 webview
  - **push (무선, 현장용)**: 백엔드 `/transmit/push-session` — cst-input `/api/session/push` 이식. 폰 쪽 push 발신은 아미큐/헬퍼 방식과 동일하게 배선 (JSESSIONID는 httpOnly라 네이티브 CookieManager 경유 — 구현 시 아미큐 발신부 확인 후 그대로 이식)
- **[로그인] 버튼 폐기 (영준님 2026-07-17)** — 로그인은 앱(계기큐)에서 사람이 함. 맥 UI = [세션 가져오기] + 세션 상태(살아있는가 + **어느 아이디인가** 표시)만.
- **계정 = 세션 아이디 자동** — 아이디는 빌려 쓰는 것(종로 여러 개·중구 여러 개, 한 공사 거의 한 아이디, 어떤 걸 써도 됨). 계정 선택 UI 불필요, 전송 기록은 세션 아이디 기준.

**첫 로그인 시 1회 조회 → 설정 고정 (영준님 2026-07-17)**:
- 세션 확보 직후 **봉인조회(getMainList 8000) + 사업조회(getBusiList)를 딱 1회** 실행 → `cons_no`(차수)·봉인 시작값을 transmit_config에 저장
- **이후 전송 루프에서 awms 봉인/사업 조회 일절 없음** — 설정된 값으로만 올림
- **등록 공사번호(cons_no)와 봉인 공사번호(seal_cons_no)는 각각 선택 가능** (영준님 2026-07-17 — 봉인차수는 계정전역이라 등록차수와 다를 수 있음). 스냅샷의 LV_CONS_NO는 봉인차수 기본값으로, 등록차수는 사업 드롭다운에서 선택.

공통:
- `SESSION` dict + `session.json` persist (아미큐 패턴 그대로)
- 세션 생존확인 = `mobMtr8000/getMainList` 재조회 (200+json이면 alive) — 전송탭 [세션확인] 배선 교체
- 세션만료(awms ~4시간) 감지 시 전송 중단 + "재로그인 후 세션 다시 가져오기" 안내

## P1.5 봉인 관리 — 전역 시퀀스, 우리 시스템이 기억 (영준님 확정 2026-07-17)

- **봉인 = 계정 무관 물리 시퀀스** — 아이디마다 awms에 저장된 봉인값은 어긋날 수 있지만 소비는 하나로 이어짐 (이 아이디에서 0111111 썼으면 다음 아이디도 0111112). 시스템이 기억하는 건 **전역 마지막 사용값 1개**(`seal_last`, config + Firebase awms_seal 전역최대의 max)
- **자릿수(zero-padding) 보존** — awms 원문 '0111111' 형식. 배정·서버저장·주입 전부 zfill(seal_width)
- 건마다 **단상 +1 / 삼상 +2** 소모 (전송 루프 중 awms 조회 없음)
- **마지막 전송이 끝나면 1회** awms 봉인 서버저장(`mobMtr8000/saveRow`, 세션 계정 앞으로) + config seal_last 갱신
- **불일치 동기화**: 다른 아이디로 로그인하면 그 계정 awms 봉인값 ≠ 시스템 기억값 → 로그인 스냅샷이 감지해 `seal_mismatch` 반환 → 프론트 알림 + **[봉인 동기화] 버튼**(`/transmit/seal-sync` = 시스템 값을 그 계정 awms에 저장)

## P2. 실행부 교체 — 맥 requests 직접 (핵심)

신규 모듈 `research/admin-validation/backend/awms_mtr_direct.py`:
- `register_replacement_direct(rep, opts) -> dict` — awms-saverow.js `registerReplacement` 이식 (단 **봉인·사업조회는 제거** — P1.5 주입값 사용)
  1. 건별 조회 = **selectCustomerInfo + getMainList(1000, 작업목록)만** (계약종별·전력·제조월·계약번호에 필요). 봉인(8000)·사업(getBusiList) 조회 없음 — requests GET (queue_saverow_builder.py lookup 함수의 CDP fetch만 requests로 교체)
  2. 철거 saveRow(5000): 기존 `build_demolition_payload` 재사용 + **removal_values 4칸 매핑 보완**(JS L494-557 기준 — py는 TODO 상태)
  3. getDetail 301키: **차수후보 다중시도 + 점증대기**(JS L744-763 — 키<100이면 강행 금지, 실패 처리)
  4. 신설 saveRow(4000, 25): 기존 `build_new_payload_from_detail` 재사용 + **CGD 칸별 0 보완**(JS L182-188 — py는 야간 무조건 0 버그 시절 로직)
  5. 완료(28): getDetail 재조회 + 시공17키 + `RE_SAVE_YN=''` + **신설사진 재전송** (JS L789-824 — py 미구현, 신규)
- 사진 파이프라인: Firebase Storage URL → 맥 requests 직다운(2026-06-04 검증: 맥=OK) → **변환 없이 그대로** multipart `files=[(field, (filename, bytes, 'image/jpeg'))]`. Storage 원본이 이미 통과규격(800px/q40, 7/3 커밋 5ed58de — "전제 확인" 절 참조). 슬롯 매핑 `DREMO_PHOTO_SLOT`(주간3/야간4/최대5/무효6) + `CREMO_ATCH_FILE_ID_3_SRC`
- 성공판정: 5000=`{result:1, consTgtSeqno}` / 4000=**평문 "1"** (다름 주의)
- 헤더: Cookie(JSESSIONID 등)+UA+Referer(`app=MOBMTR`) — 아미큐 `_headers()` 이식. ★MOBCST 교차호출 405

app.py 배선:
- `/transmit/run`의 `_remote_register` 호출 1곳(L4069) → `exec_mode` 분기: `direct`(기본) / `cdp`(기존 코드 보존, 폴백)
- 봉인배정·`awms_synced` 마킹·모니터·로그·전송탭 UI = **전부 그대로 재사용** (변경 0)

## P3. 최종봉인 서버저장 (P1.5와 연동)

- 배치의 **마지막 건 전송이 끝나면** 계정별 `next_after` 값을 `mobMtr8000/saveRow`(JSON, X-XSRF 헤더)로 1회 저장 (JS `_sealPlusOne` body 이식)
- 실패해도 전송 자체는 성공 처리 + 경고 로그 (봉인설정은 수동 보정 가능)

## P4. 사후검증 — 필드 대조 → 전송완료 확정 (옵션 토글)

전송 배치 완료 후(또는 전송탭 [검증] 버튼):
1. `getMainList(1000)`으로 오늘 올린 건 일괄 재조회 → 존재 + WORK_STEP=28 확인
2. 건별 `getDetail` → 대조: 신설계기번호(CREMO_WHM_NO)·봉인(SEAL_NO/NO2)·철거지침(DGD_*=우리 removal_values)·신설지침(CGD_*=0)·제조월(CREMO_PRDC_YM)
3. 불일치 → 전송로그에 빨간 경고 + Firebase `awms_verify_mismatch` 기록 (awms_synced는 유지 — 등록 자체는 됐으므로)
- **필드 대조까지 통과한 건 = 전송완료 확정 (영준님 2026-07-17)** — 이후로는 awms 재조회 없이 **우리 시스템(awms_synced) 기준으로만** 전송완료 취급. 재확인 불필요.
- 전송탭 토글 `[전송 후 awms 검증]` (기본 ON) — 30건이면 재조회 31콜, ~1분

## 제작 방식 (영준님 지시 2026-07-17)

- **지금은 기존 소스 기준으로 판단해 전부 제작** — awms 로그인(실세션)은 제작 완료 후 영준님이 열어줄 때까지 **불가**(관리 폰 아님). 그때까지 라이브 호출 없는 dry-run 검증만.
- **Fable(PM) 주도 멀티에이전트 분업**: 모듈·배선·프론트를 에이전트에 나눠 병렬 제작, Fable이 결과를 회수·검토하고 결정이 나올 때까지 유기적으로 재지시.
- dry-run 검증 수단: `queue_saverow_builder.py`의 recording 대조 테스트(기존) + payload 스냅샷 비교 + 모의 세션 유닛테스트.

## 검증 게이트 (사고 방지 — 순서 고정, ★awms 로그인 개방 후 실행)

1. **G1**: 더미계기(0999...) 1건 direct 실등록 → awms 화면 확인 → resetRows 삭제
2. **G2**: 실계기 1건 (검증완료건 중 1건) → 28까지 + 사진 awms 확인 + 사후검증 대조 통과
3. **G3**: 소배치 3~5건 → 봉인 연속성·최종봉인 저장 확인
4. 이후 실운영. G1~G2 사이 실패 시 CDP 폴백 모드로 운영 지속 가능

## 전제 확인 (영준님 지시 2026-07-17 — 조사 중)

- **날짜 스코프: 확인 완료 (2026-07-17 구조분석)** — 전송탭은 이미 날짜 스코프를 100% 따름. `transmitLoadList()`가 검증탭의 `#dateInput` 날짜로 `GET /results?date=`를 불러 **그 날짜의 isVerified && !awms_synced 건만** [미전송]에 표시. 날짜 미선택 시 목록 자체가 안 뜸. "전체 기간" 모드 없음. → 신규 작업(P0 워처·P2 직접전송·P4 사후검증)도 전부 이 날짜 스코프 단위로 동작하게 구현 (배치=선택 날짜의 건들).
- **사진 신규 규격: 확인 완료 (2026-07-17 조사)** — 옛 "2992px/700KB 하한"은 **허구로 판명**(2026-07-03 세션로그, 실검증: 54KB/800px 통과). 현행 통과 검증 하한 = **800px / JPEG q40 / ICC 제거**(커밋 5ed58de, 2026-07-02 영준님 실측 — awms 통과+OCR 판독 겸용 하한). 종로맵·보조앱이 7/3부터 이 규격으로 Storage에 저장 중이므로 **전송탭은 Storage 원본을 직다운해 그대로 올리면 됨**(변환 불필요). 단, 7/3 이전 옛 사진(원본 4096/q85, 1~2MB)도 상한 검증이 없어 그대로 통과. 최종 확정은 G1 더미 1건으로 실측.
