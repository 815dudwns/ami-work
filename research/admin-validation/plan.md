## 0. 한 줄 정의
사장님(데이터검증업체)이 **실효 계기교체 데이터를 한눈에 관리·검증하는 데스크톱 웹 포털**. 핵심은 **awms(한전) 입력값이 실제 작업값과 맞는지 일괄 검증**해 오류를 미리 잡아주는 것. 점진적으로 종합 관제 포털로 확장.

## 1. 사업 맥락 (왜)
- 데이터관리업체 = 한전 ↔ 작업자(시공업체) **브릿지**. 한전 요구 양식·서류·리스트·모니터링·인입설계를 대리. 그중 **실효**를 우리가 먼저.
- 사용자 = **데이터검증 사장님(30년 베테랑) 1명**. 궁극 목표 = 자동화로 직원 없이 혼자 운영(= 솔루션의 셀링포인트, 사람 절감).
- 검증의 가치: awms는 한 번 잘못 넣으면 수정이 지옥(작업자 OTP 일일이 받아 한전앱에서 수정). **검증이 미리 정확히 짚어줘 그 노동을 줄임.**
- 수익 구조: **지도·검증 포털 = 업체 몫**(사장님께 제공) / **자동업로드(계기큐, awms 자동) = 작업자 몫(유료, 별도 수입)**.
- 우리가 줄 것 = 관리자 포털 + 사용 매뉴얼. 사장님이 줄 것 = 실효 데이터(아직 미수령).

## 2. 제품 성격
단순 검증 도구가 아니라 **종합 관리 포털**(통계 + 데이터 열람 + 검증 + 이력 …). 영준님이 사장님 업무를 배워가며 **기능을 계속 얹는다** → 그래서 "수정·확장이 쉬운 뼈대"가 핵심.

## 3. v1 범위 (사장님 데모용, 종로 샘플)

### 화면 구성
```
[검증]  [통계]  [이력]            ← 상단 탭
─────────────────────────────────────────────
■ 검증 탭 (메인)
 [날짜 ▼] [검증 실행]            필터: [전체 | 문제건만]
 → 한 번 누르면 그날 전체를 자동 대조 (입력값 vs 사진 OCR)

 결과 목록 (작업 이벤트 = daily_seq 단위, 한 줄씩)
  작업순번 · 고객번호(01-형식) · 철거계기번호 · 신설계기번호 · 주간·야간·최대전력·무효전력 · 검증상태
   (계기번호 타입 자리 색 강조 — 종로맵 방식)
   └ 한 줄 클릭 → [검증 모달] 사진 크게 + 입력값 vs OCR 대조 + (문제건) 판정 입력
       LLM(Claude 비전) 1차 제안 → 사람은 확인·수정

■ 통계 탭   진행 현황 (차수명 가져와 필터링 수준. 금액 정산 없음)
■ 이력 탭   누가/언제/어떤 값을 어떻게 고쳤는지 기록 (나중 관제탑의 토대)
```

### 검증 흐름 (핵심: 일괄)
1. [검증 실행] 1회 → 전체 자동 대조 (등록할 때마다 X, 한 번에 O)
2. 자동 통과분은 안 봐도 됨 → **사람은 "문제건만"** 모달로 개별 판정
3. 판정 결과 기록 + 이력 남김

### 데이터 보기 단위
- **철거→신설 한 작업 = 하나의 이벤트(daily_seq) = 한 행.** 펼치면 그 건 전부(철거/신설 번호, 검침값4, 사진들, OCR대조, 검증상태).

5. **사람 판정(need_human)** — 사진보고 판정→/verdict. [페이지 ✅].

## 6c. 스왑 교정 (할당 오류 정정) — 설계 2026-06-27 (영준님 브레인스토밍)

### 왜 (핵심 통찰)
- 종로맵 = **있는 데이터(site-data 준공리스트)에 작업을 "할당"**. 작업자가 레코드를 만드는 게 아니라 기존 계기 칸에 신설/검침/사진을 붙임(99% 기존, 1% 계기추가).
- **할당 잘못 = 작업을 엉뚱한 기존 칸에 통째로 붙임.** 사진만 바뀐 게 아니라 그 칸의 작업데이터 전부가 옆 계기 것.
- **철거계기번호 OCR 검증 = 이 할당오류 탐지기.** 철거사진 OCR이 키(할당된 철거번호)와 다르면 = 할당 의심. (OCR규칙 §3 "엉뚱계기 철거 need_human" 이게 그 신호.)
- 실증 92·93(명륜3가 121-2): 키 29171233026의 철거사진 OCR=29171233126(옆 칸). 검침·신설 OCR은 내부일관돼 auto지만 묶음이 통째로 옆 칸에 붙음.

### 모델
- **키(철거번호)는 고정** = 고객(site-data) 연결. 키 바꾸면 고객연결 깨짐.
- **두 칸의 "작업 데이터"를 통째 교환.** 필드 골라내기 X — 작업자가 넣은 전부 스왑.
- **자동 스왑은 안 함**(규칙 AUTO_CORRECT 유지) — "스왑 의심"만 띄우고 사장님이 [맞바꾸기 확정].

### 필드 분류 (SWAP vs STAY) — ★구현 핵심
- **STAY(키/고객/계약 속성, 그 자리 고정)**: `old_meter_id`(키), `계약전력`,`계약종별`,`cntr_clas`,`cntr_no`,`cntr_pwr`(계약), `awms_cons_no`,`awms_cons_tgt_seqno`,`awms_reg_id`(awms 작업대상 식별자=계기 귀속), `source`,`imported_at`(import 메타).
- **SWAP(작업자가 넣은 작업 결과)**: `new_meter_id`,`new_meter_photo`,`new_meter_photo_thumb`,`new_meter_mfg_ym`,`old_meter_photo`,`old_meter_photo_thumb`,`removal_values`,`removal_value`,`removal_photos`,`removal_lcd_photos`,`removal_lcd_regions`,`removal_lcd_flags`,`daily_seq`,`replaced_at`,`draft`,`remark`,`worker`,`worker_name`,`last_edited_at`,`last_edited_by`,`extra_data`,`quarantine`.
- **awms 동기화결과**(`awms_response`,`awms_synced`,`awms_synced_at`,`awms_error`,`awms_error_at`): 스왑하면 awms와 종로가 어긋남(awms는 잘못 등록된 상태 그대로). → **스왑 시 두 칸 awms_synced=false로 떨어뜨리고 "awms 수정 필요" 표시**(자동 awms수정 안 함). 안전.
- ★구현은 SWAP 화이트리스트 명시. 목록에 없는 새 필드는 보수적으로 STAY(안 건드림).

### 안전장치
- **롤백 = 두 레코드 full 스냅샷 저장 후 복원**(필드선택 무관 bulletproof). audit action='swap', 두 mid·스냅샷·복원키 기록.
- **edit-then-swap 꼬임 가드(영준님 경고)**: 스왑 대상 두 건 중 개별 `apply` 이력 있으면 차단/경고("이미 값 수정됨—스왑 시 꼬임"). 스왑 의심 건은 모달서 개별 [확정 반영] 숨기고 [맞바꾸기]로 유도.
- live 재조회 후 스왑(캐시 금지). 같은 주소·둘 다 존재 확인.

### 진입점
- ① 자동: 검증 후 "A철거OCR=B키(같은 주소)" 탐지 → 확인필요에 "스왑 의심" 묶음 → [맞바꾸기 확정].
- ② 수동: 어떤 건이든 모달 "다른 건과 맞바꾸기" → 같은 주소 후보/검색 → 확정.

### 구현 대상
- 백엔드 `/swap`(원자교환+스냅샷롤백+가드), 스왑의심 탐지(/results 또는 신규), `/rollback`에 action='swap' 분기(두 레코드 스냅샷 복원).
- 프론트: 확인필요 "스왑 의심" 묶음, 모달 [맞바꾸기](자동/수동), 스왑의심 건 개별수정 잠금.
