# 데이터 검증관리자 → 데이터 워크벤치 재설계 (정본)

> 2026-07-02 영준님 브레인스토밍 확정. 사례조사 근거: `데이터그리드_재설계_사례조사.md`.
> 이 문서가 재설계 방향의 단일 출처. 기능 추가 시 여기 갱신.

## 문제 진단 (왜 지금 구조가 어긋났나)
오늘 겪은 버그 3개가 **전부 같은 뿌리**:
- 스왑이 workStatus만 고치고 CSV를 안 고쳐 검증관리자만 어긋남 (중복 4행)
- worker_missing 80건 — 작업자가 검침값 넣었는데 CSV는 빈값, 재검증해도 안 풀림 (daily_cycle:450 `if ts in st: continue` 증분 skip)
- 작업자 최신 작업이 화면에 반영 안 됨

뿌리 = **원본(workStatus/DB)과 검증결과(CSV)가 분리 + 검증이 "한 번 돌리는 배치"**. CSV는 검증 순간의 스냅샷이라 DB가 바뀌어도 안 따라오고, "검증 탭"이라는 이름부터 검증이 주인공이고 데이터가 부산물.

## 비전 (주객 전도)
| 지금 | 목표 |
|---|---|
| 검증 도구 (배치 실행) | **데이터 워크벤치** (원본을 보는 곳) |
| 검증 결과가 주인공 | **데이터가 주인공**, 검증은 자동 레이어 |
| "검증 실행" 버튼 | 정합성은 **바로바로 자동**, OCR만 수동/자동 |
| 검증상태만 봄 | 원본 보고·묶고·필터링·판정 |

## 확정 설계

### 1. 뷰 구조 — "날짜/순번별"이 기본, 데이터 모델은 멀티 구성 대비
- 화면은 지금처럼 날짜별·순번별 (완전 스프레드시트 아님 — 사례조사 시사점7: 사진·중첩 구조라 마스터-디테일이 맞음)
- 내부 데이터 모델은 **"필터로 구성한 레코드 집합"** 으로 추상화 → 한 화면에 여러 날짜·여러 차수가 겹쳐도 됨
- 필터: 날짜 / **차수** / 상태(미완료·문제만·검증대기) / (미래) 멀티날짜 특수필터

### 2. 검증 2층 — 정합성 상시, OCR 수동/자동
- **정합성(규칙): 데이터 들어오면 즉시** (빈값·11자리·자릿수·타입·단상삼상칸). `validation_rules.py` 선언적 → on-read + 배치 공용
- **OCR(PARSeq·Apple Vision): 무거우니 수동/자동 토글** (완료 시 자동 큐 옵션 + 수동 버튼)
- 상태: 자동통과 / 확인필요 / **검증대기(OCR 미실행)** / 완료
- 행동 = **판정** (확인완료·확인불가·종로값교정·스왑). awms는 값수정 불가라 인라인 즉시수정 아님 (사례조사 시사점4)
- 검증완료 → **awms 등록** (옆 세션이 이식 중인 awms 큐와 연결, 미래엔 자동)

### 3. 단일 진실 = DB(workStatus)
- CSV 스냅샷 폐기 (또는 OCR 결과 부가레이어로만) → 스왑·재입력 즉시 반영, worker_missing 자동 갱신

## 로드맵 (기존 admin-validate 점진 개조)
| 단계 | 내용 | 효과 |
|---|---|---|
| **1** | 정합성 규칙 조회 즉시로 (`validation_rules.py`, on-read) | worker_missing·재검증 문제 바로 해소, CSV 의존 축소 |
| 2 | 단일 진실 전환 (workStatus 직접, CSV는 OCR값만) | 스냅샷 어긋남 소멸 |
| 3 | 필터 확장 (차수·미완료·문제만·멀티날짜) | 필터 요구 충족 |
| 4 | 검증대기 상태 + OCR 수동/자동 토글 | 배치 불확실성 해소 |
| 5 | awms 등록 연결 (옆 세션 큐 통합) | 검증→등록 원클릭 |

## 옆 세션 조율
옆 세션이 같은 admin-validate에서 **① 성능(캐시 TTL) ② awms 큐 이식** 진행 중.
- 1단계(정합성 on-read)의 `validation_rules.py`는 새 파일 → 안 겹침. `daily_cycle.py`도 옆 세션 미접촉. **먼저 착수 가능**
- app.py `/results` 통합, 2·5단계는 겹치니 순서 조율 필요

## 사례조사 핵심 시사점 (근거)
1. 파생 검증상태 열이 그리드+검증을 하나로 (AG Grid cellClassRules / MUI X 마스터-디테일)
2. 가벼운 규칙=조회 즉시 / OCR=배치, 같은 상태열에 표면화
3. 예외기반 검토(EBPR) = "문제건만" 필터의 이론적 근거 (MES·제약 배치기록)
4. awms 수정 불가 → "판정(verdict)" 중심 UX (회계 감사 도구 모델)
5. "검증대기" 상태 명시 → 배치 불확실성 해소
6. `validation_rules.py` 선언적 코드화 → 규칙 유지보수 일원화 (dbt/GE)
7. 마스터-디테일 > 평면 스프레드시트 (중첩 구조·사진)
