## 1. selectMtrlUseYn 응답에 통신방식이 오는가? → **NO (확정)**

capture_full 엔트리 54/56/58 (`mobMtl1000/selectMtrlUseYn?vBarcdQr=01249852054&vGubun=M`)
실제 응답:
```json
{"AFTER_RESULT":"N","MTRL_NO":"","BEFORE_RESULT":"N","MNFCT_YM":"","RESULT":"N"}
```
= 자재 사용여부(중복사용) 체크 전용. **통신방식/모뎀종류 필드 없음.**

다른 후보 엔드포인트도 통신방식 안 줌:
- `getBusiMacConnection?MAC_MODEM=01249852054` → 응답 본문이 그냥 `0` (연결 카운트/플래그)
- recorder `selectBarcdQr`(mobMtl2010, 자재출고) → `INST_M:""`, `INST_S:""` (신규모뎀이라 빈값)

**결론: "맥 스캔 → awms 검색 → 통신방식 자동 획득" 경로는 불가.** awms는 신규 스캔 모뎀의
통신방식을 응답으로 돌려주지 않는다(설치 전 자재라 INST_S 비어있음).

## 2. 스캔값(vBarcdQr) prefix ↔ 통신방식 → **데이터 부족 (012만 관측)**

recorder에서 실제 스캔된 모뎀 1종뿐:
- QR 자재ID `G1S349849692` → 변환 → `01249849692` (vBarcdQr). 11자리 `012...`.
- capture에도 `01249852054`, `01248232297` 등 전부 `012...` 11자리.

`075`/`085`는 **모뎀 스캔값이 아니라 계기번호 prefix**다 (보강현황 col21 계기번호:
`075`로 시작 13,780건, `245`/`251`/`455` 등도 계기번호). getSigModemList의 METER_ID도
`07530065461`처럼 075로 시작 → 계기번호임. 모뎀 스캔 prefix로 착각한 것.

| 스캔값 형태 | 관측 | 통신방식 |
|---|---|---|
| `012...` 11자리 | recorder+capture 다수 | LTE 계열 (lte_IV / smgw-c) — 영준님 확인과 일치 |
| 그 외 prefix | **관측 0건** | 미상 (데이터 없음) |

DCU 계열(ks-plc/k-dcu/hpgp) 스캔값 형태는 **샘플이 없어 확정 불가** (추측 금지).

## 3. 엑셀(col20 모뎀 MAC) prefix ↔ 통신방식 (165,688행 전수)

주의: col17 통신방식은 **기존(before) 모뎀** 기준이고, col20 MAC도 그 기존 모뎀/DCU의 MAC.
DCU 계열은 col20에 DCU MAC(hex)이, LTE 계열은 16자리 모뎀바코드가 들어가 **혼재** → prefix가
통신방식과 1:1로 깨끗하지 않음. 그래도 **hex DCU MAC prefix는 강한 신호**다:

| col20 prefix | 건수 | 주 통신방식 |
|---|---|---|
| `847207` + 7번째 `0` | 14,704 | **K-DCU 83%** (12,215) |
| `847207` + 7번째 `E` | 1,244 | **K-DCU 89%** (1,113) |
| `847207` + 7번째 `B` | 1,534 | **PLC 97%** (1,482) |
| `847207` + 7번째 `C` | 112 | **PLC 98%** (110) |
| `847207` + 7번째 `D` | 3,741 | **PLC 96%** (3,610) |
| `E0AEED` (hex) | 19,417 | **PLC 96%** (18,580) |
| `44B433` (hex) | 4,000 | **HPGP 98%** (3,902) |
| `0014B0` (hex) | 273 | **HPGP 97%** (264) |
| `AC5E8C` (hex) | 1,972 | K-DCU 67% / PLC 27% (혼재) |
| 16자리 숫자 `3438*/0504*/0409*/0505*` | 다수 | LTE_IV/PLC/K-DCU/SMGW-C **전부 섞임** (판별 불가) |

→ 설계문서의 "847207 7번째 0/E=k-dcu, B/C/D=ks-plc" 패턴은 **대체로 맞음**(각 90%+).
hex `44B433`/`0014B05`=hpgp도 맞음. 단 **16자리 숫자 MAC은 통신방식을 가르지 못함** (col20이
기존모뎀이라 그 자체가 여러 방식 혼재). col20에 `012`로 시작하는 값은 **0건** — 스캔값과 엑셀
저장형식은 완전히 다른 인코딩.

## 4. DCU ID 끝 2자리 ↔ 통신방식

**중요 반증: 모든 행(165,688)이 DCU ID(col15)를 보유한다 — LTE_IV/SMGW-C도 빈값 아님.**
설계문서 단서 #3("lte_IV/smgw-c는 DCU 빈값")은 이 데이터셋에서 **거짓**.

끝 2자리 패턴은 계열별로 다르긴 함(판별 보조 신호일 뿐, 단독 판별 불가):
| 통신방식 | DCU ID 끝2자리 |
|---|---|
| K-DCU | `5M`, `5S`, `6S`, `6M` (M=마스터/S=슬레이브, 5/6차) |
| PLC | `44`, `39`, `00`, `01`, `29`, `31`… (숫자, 분산) |
| HPGP | `39`, `41`, `45` |
| LTE_IV | `51`, `41`, `53`, `62` (숫자) |
| SMGW-C | 분산 (`42`,`41`,`51`,`59`…) |

→ K-DCU만 끝2자리에 `M`/`S` 알파벳이 들어가 식별성 높음. 나머지는 겹침.

## 5. 최종 권장 판별 로직

awms 검색(a)은 **불가**(§1). 스캔 prefix(b)는 `012`=LTE계열만 확정, 나머지 미관측(§2).
따라서 **단일 단서로는 완결 불가**. 권장:

1. **1순위 — site-data.json의 기존 `통신방식` 필드 사용.** site-data 26,588건 전부
   계기번호별 `통신방식`(PLC/LTE_IV/K-DCU/HPGP/SMGW-C/LTE)을 이미 보유(보강현황 col17 유래).
   DataPush는 계기번호로 site-data 조회 → 통신방식 즉시 획득. **MAC 파싱 불필요.**
   - 단 이는 **기존(before) 모뎀 기준**. 실제 시공 후 방식이 바뀌면(예: 다수가 PLC→SMGW-C
     마이그레이션, col29 참고) 어긋남.
2. **2순위 보강 — 스캔값 prefix `012`** → LTE 계열(lte_IV 또는 smgw-c)로 좁힘.
3. **3순위 보강 — site-data DCUID 끝2자리** `M`/`S` 있으면 K-DCU 강한 후보.

awms saveAct INST_S suffix 코드는 capture의 getCommonCode(HW40xx)로 **확정**:
`10=ks-plc, 20=hpgp, 40=LTE, 70=lte_IV, 80=iot-plc, 90=k-dcu, 85=IP-HPGP`.

## 6. lte_IV vs smgw-c 구분 → **현재 데이터로 불가 (추측 금지)**

- 둘 다 스캔값 `012...` LTE 계열로 추정 — prefix로 안 갈림.
- **계기타입(AMIGO) 가설 반증**: SMGW-C 654행의 계기타입은 보안계기 339/G타입 167/AE타입 148
  — AMIGO 전용 타입이 없고 분포가 다른 방식과 다를 바 없음. **계기유형으로 split 불가.**
- getCommonCode HW40xx 테이블엔 `92=smgw-c` 자체가 **없음**. SMGW-C는 CST023에서 코드 `24`.
  → 설계문서의 "INST_S suffix 92=smgw-c" 는 **미검증/근거없음**. 실제 AMIGO 시공 1건
  saveAct payload 캡처 필요(현재 recorder는 saveAct 요청바디 미저장 — 응답만 `result:1`).

**lte_IV/smgw-c 자동구분은 현 단서로 해결 불가.** 작업자 수동 선택 또는 AMIGO 시공 1건
saveAct 캡처로 INST_S 실값 확인이 유일한 길.

### C. 편차의 원인 = 현장변수 (노이즈, 판별에서 제외)
변대주 통신방식이 k-dcu/ks-plc인데 실제 MAC이 LTE거나 다른 PLC로 찍히는 이유:
- 인입공사로 **변대주 자체가 바뀜**.
- 변대에서 **DCU↔모뎀 통신불량 → LTE로 대체 시공**.
- LTE로 찍힌 건 = "PLC 시공했으나 미연계→LTE" 또는 "LTE 시공" → **ks-plc/k-dcu 판별에선 무시**.
