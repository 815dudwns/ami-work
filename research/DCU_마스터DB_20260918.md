# DCU 마스터 DB — 스키마·갱신절차·원칙 (2026-09-18, 통신팀)

영준님 지시: "리뷰 반영한, 우리가 항상 쓸 것을 DB 로 만들어라"

DCU 정보가 `dcu_all`·`dcu_review`·`dcu_removal`·`dcu_removal_keep` 넷으로 흩어져 있었고,
리스트마다 상태값을 **복사해 박아서 낡았다.** 그래서 상시 참조용 마스터를 하나 뒀다.

---

## ★원칙 1 — 리스트에 DCU 상태값을 복사해 넣지 마라

미청구·실효 같은 **리스트에는 `DCUID` 만 둔다.** 회선상태·장애여부처럼 시시각각 바뀌는 값은
`dcu_master` 를 조회해서 읽는다.

복사해 두면 대장이 갱신돼도 리스트는 옛 값을 들고 있게 되고, **리스트 수만큼 진실이 갈린다.**
실제로 미청구 데이터셋이 그래서 `DCU회선상태`·`DCU장애여부` 를 뺐다.

## ★원칙 2 — 매칭 축을 넘나들지 마라

> "변대주명 매칭 · 전산화번호(변대주번호) 매칭 · DCUID 매칭 — 끼리끼리 해야만 한다." (영준님)

축은 셋이고 서로 **유도하지 않는다.**
- 이름으로 찾은 것에 번호를 붙이지 않는다(표기 변형·동명이 있다)
- DCUID 앞 8자리로 변대주번호를 만들어 **본값에 넣지 않는다**
- 축을 넘을 수밖에 없으면 **`<필드>_유도`** 에 넣고 본값에 섞지 않는다
- 검증 불가한 유도값은 **값을 빼고 출처만 남긴다** — 빈칸이 틀린 값보다 낫다

※실측: 이 대장 안에서는 `DCU_ID[:8] == 변대주번호` 가 **19,007/19,007 예외 없음**이다.
  그래도 **대장에 없는 DCUID** 에 그 규칙을 적용한 값은 확인할 길이 없으므로 본값에 넣지 않는다.

## 테이블 `dcu_master` (ami.db)

키 = `DCU_ID`(10자리). 인덱스는 `DCU_ID`(unique) · `변대주번호` · `변대주명` · `지사` ·
`철거판정` · `회선상태`. **마스터 안에서 축끼리 서로 유도해 채우지 않는다 — 원본에 없으면 빈값이다.**

| 열 | 출처 | 비고 |
|---|---|---|
| `DCU_ID` | dcu_all | 키 |
| `변대주번호` `변대주명` `지사` `차수` | dcu_all | 원본 그대로 |
| `인입망통신방식` `장애여부` `회선상태` `DCU_IP` `통신사` | dcu_all | |
| `성공전체계기` `서버시간` `DCU등록시간` `비고` | dcu_all | |
| `전체호수` `LTE전환호수` `잔여호수` | dcu_review | 175건만 있다 |
| **`철거판정`** | 아래 규칙 | `해지` \| `유지` \| `미판정` — **빈값 없음** |
| `보강대상여부` | dcu_review | `보강대상` 또는 빈값 |
| `src_snapshot` `updated_at` | 메타 | 값의 기준일 / 적재 시각 |

### 철거판정 규칙
1. `dcu_review.검토`(해지/유지) — 판정 정본(간선망_해지_정지대상.xlsx **검토 시트**)
2. 없으면 `dcu_all.비고` 가 해지/유지일 때 그 값
3. 그 외 **`미판정`**

**빈값을 쓰지 않는다** — 빈값이면 '판정이 없는 것'인지 '아직 안 붙인 것'인지 구별이 안 된다.

※실측: 1)과 2)는 175건에서 **100% 일치**하고(해지 164·유지 11), 2)가 해지를 **119건 더**
갖고 있다. 그래서 2)까지 봐야 판정이 294건이 된다.

### 원천 파일

| `dcu_review` | 175 | 같은 파일, **검토 시트** | 20260806 |

★`dcu_removal`·`dcu_removal_keep` 은 `dcu_review` 175개를 해지/유지로 갈라 놓은 **같은 집합**이다
(실측: removal ⊂ review, keep ⊂ review, 합이 정확히 175). 따로 읽을 값이 없어 마스터에 넣지 않는다.

## 갱신

```bash
python3 scripts/build_dcu_master.py              # dcu_all 최신 snapshot 으로 적재
python3 scripts/build_dcu_master.py --snapshot 20260806
python3 scripts/build_dcu_master.py --dry        # 무엇이 바뀌는지만 본다
```

새 DCU 현황·검토 엑셀이 오면 먼저 `scripts/xlsx_to_db.py` 로 적재해 새 snapshot 을 만들고
위를 돌린다.

- **같은 snapshot 재적재는 멱등**이다(변경 0, 이력 0).
- **새 snapshot 은 값을 갱신하고 이전 값을 `dcu_master_history` 에 남긴다** —
  `DCU_ID · 필드 · 이전값 · 새값 · snapshot_before · snapshot_after · 기록시각`.
  무엇이 언제 어떻게 바뀌었는지 되짚을 수 있다.
