# 통신팀(MOBCST1000) 설비등록 조사 — 아미큐 재빌드용

> 목적: 아미큐(ami-queue)를 **awms 통신팀 마스터/슬레이브 모뎀 설비등록 화면 복제 + 로컬저장(딜레이X) + 사진 EXIF 시간시프트 + saveAct 건별 전송**으로 재빌드. 2026-06-13 조사.

## 재빌드 방향 (영준님 확정)
1. awms 통신팀 설비등록(마스터/슬레이브 모뎀결합, `saveAct`) 화면을 **로컬 UI로 복제**
2. 입력 즉시 **로컬 저장**(딜레이 X, 임시저장 25 없음 — 통신팀은 saveAct가 곧 28 완료)
3. 전송 시 **사진 EXIF 촬영시각을 지정 작업시각으로 시프트**(ami-work `admin.html` 사진등록 모달 방식: piexif로 DateTimeOriginal/DateTime/DateTimeDigitized 변경, 상대간격 유지 전체 시프트)
4. **`saveAct`로 건별 전송**(WORK_STEP=28), 일괄 아님
5. OTP 감지 내장(헬퍼 패턴 [[awms_otp_amiqueue_embed]])

## API 구조 (실측 — `MOBCST1000.api.js` 전문 확인)
베이스 `/ami/mob/cst/mobCst1000/`. 모두 axios.
| 함수 | 메소드 | 엔드포인트 | 용도 |
|---|---|---|---|
| getMainList | GET (params) | `/getMainList` | 작업목록 |
| getDetail | GET (params) | `/getDetail` | 상세(폼 채울 값) |
| **saveAct** | **POST (params=body)** | `/saveAct` | **작업저장 → WORK_STEP=28** |
| sendSelections | POST | `/sendSelections` | 전송 → 29 |
| revokeSelections / deleteRows / checkDuplication | POST | | 취소/삭제/중복 |
| checkMeterDuplication / getBusiMacConnection / getBusiMacBoxConnection | GET | | 계기중복/맥연결/박스결합 |
| getBusiList / getDept / getCommonCode / getUserList / getUserWorkGroup | GET | | 차수/부서/코드/작업자 |

- 임시저장(25) 없음. **통신팀은 saveAct가 곧 완료(28)**, sendSelections로 29(전송완료).
- 기본 파라미터: `FLAG=M10, DEPT1=3970, DEPT2=7793`.

## saveAct 페이로드 (레퍼런스 8.5 — 64필드, 추가 캡쳐 필요)
- 계기별 다름: `INSTR_NUM`, `MODEM_DIV`(+_NM), `MB_METER_ID`, `ATCH_FILE_ID_3/4/5/6`(사진).
  - `ATCH_FILE_ID_3`=마스터 시공전(슬레이브 공유), `_4`=모뎀맥 사진(awms 자동공유), `_5/_6`=계기별 고유.
- `BUNGI`(무선/유선), `WORK_DIV=M1010`, 공통: `BUSI_NUM, DEPT1/2, INST_M/S, WORK_STEP=28, FLAG=M10`.
- ★주의: 한 계기 페이로드를 다른 계기에 복사 금지(마스터 div=20 격하/사진 뒤바뀜, result:1로 조용히 깨짐). 각 계기 currentRow에서 추출.
- 맥 변경 = 모뎀 재결합(saveAct로는 안 바뀜): getDetail→getSigModemList→checkDuplication→saveAct. 마스터 먼저.

## ★ saveAct 직접호출 실측 검증 (2026-06-13)
awms 폼 조작(vue+인식+사진) 없이 **API 직접 호출**로 등록/삭제 전체 제어 확인. **통신팀은 삭제 자유라 안전 테스트 가능.**
- `mobCst1000Api`(전역) `.saveAct(params)` — params **객체** 전달 → `{result:1, atchFileId3:"", atchFileId4:""}`. **사진 없이도 result:1**(atchFileId 빈값).
- 보낸 params가 `getMainList`에 **그대로 반영**(INST_M/INST_S/MODEM_DIV/MAC_MODEM/MB_*/FCLTY_DIV/BUSI_NUM). → **saveAct 페이로드 ≈ getMainList 필드 + design §6 빌더**.
- **마스터+슬레이브 결합 검증**: 같은 `MAC_MODEM` + 마스터 `MODEM_DIV=10`·`MB_METER_ID=자기`, 슬레이브 `MODEM_DIV=20`·`MB_METER_ID=마스터계기`, 둘 다 `MB_CNT=함내수` → 조회 시 **`MB_REG_CNT=2`로 묶임**. 둘 다 result:1.
- `mobCst1000Api.deleteRows([행])` (getMainList 행객체 배열) → `result:1` 삭제 확정. 복합키 INSTR_NUM+MAC_MODEM.
- 최소 등록 params(검증됨): `DEPT1=3970, DEPT2=7793, WORK_DIV=M1010, FLAG=M10, WORK_STEP=28, MTR_WITH_YN=N, FCLTY_DIV, MODEM_DIV, INSTR_NUM, INST_M, INST_S, MAC_MODEM, MB_METER_ID, MB_CNT, BUSI_NUM=C11G250023, BUNGI`.

### ★ saveAct 500 원인=봉인 빈문자열, 빌더 omit으로 해결 (실측 검증 2026-06-13)
- **500 원인**: 빌더가 봉인(SEAL_BOX1/2·SEAL_METER1/2·SEAL_OUTER1/2·ENCL/METR/OTSD_SEAL_VAL) 미설정 시 **빈문자열("")** 전송 → awms는 Java라 `parseInt("")` 예외 → **500**. "필드 누락(null-safe)"과 "필드=빈문자열(파싱폭발)"은 서버에서 다른 경로. getDetail에 빈값으로 보여도 POST에 ""보내면 안전 아님.
- **해결**: `saveact-builder.js` buildSaveActRows return 직전 **옵셔널 빈값 omit** — `OMIT_IF_EMPTY=[SEAL_BOX1/2, SEAL_METER1/2, SEAL_OUTER1/2, ENCL/METR/OTSD_SEAL_VAL, WORKER2_SEQ, WORKER3_SEQ, DCU_ID]` ''/null이면 키 삭제. 필수(INST_*/MB_*/MAC/INSTR_NUM)는 유지. BUNGI=''는 무관(문자열). → **500→200 전환, result:1 INSERT 실측**(09990000077 등록→deleteRows). 중복계기는 200+`CODE:670 unique constraint`(형식정상·비즈니스 중복).
- **MTR_WITH_YN=Y** (위 "N"은 ami 단독, 통신팀 모뎀시공은 Y — 실존행·빌더 보정).
- **마스터+슬레이브+사진 풀검증**: MB_REG_CNT=2 결합 + FormData Blob 사진 atchFileId3/4(F100xxxx) + deleteRows 정리. 빌더 결합 로직 정확.
- **CDP 검증 주의**: 한 eval에 getMainList(pRowCount 3000)+saveAct다건+deleteRows 묶으면 **90s timeout → 단계 분리**(단건 saveAct는 빠름). `mobCst1000Api`는 MOBCST 시공관리화면(`index.html?app=MOBCST&menu=01010000`)에서만 전역, vue라 CDP 메뉴진입 막힘(수동 진입). 테스트 더미 계기 `09990000006`/`09991000004`(WORK_STEP28 DATA_NUM빈값, 삭제자유) — 빌릴 땐 새 더미번호로 INSERT→deleteRows. 메모리 [[awms_saveact_500_fix]].

### ★ 박스결합(2/2) = 대표계기 기준, 맥 아님 (실측 2026-06-13)
- **같은 맥 + 같은 대표(MB_METER_ID)** → `MB_REG_CNT=2`(묶임). **같은 맥 + 다른 대표** → 각 `MB_REG_CNT=1`(분리), `getBusiMacBoxConnection(맥,대표)`=대표별 1.
- → **박스결합은 `MB_METER_ID`(대표계기) 기준.** 슬레이브를 마스터에 묶으려면 슬레이브 `MB_METER_ID`=마스터 계기번호.
- **맥 연결은 saveAct로 안 됨**: `getBusiMacConnection(맥)`=0 (saveAct로 2건 넣어도). = 8.5 "맥변경=모뎀 재결합(saveAct 아님)". 모뎀결합 테이블 별도(getSigModemList/checkDuplication). 헬퍼 "모뎀맥 awms 자동공유"가 이 영역 — 빌더에 별도 반영 검토.

## ★ 필드 채우는 법칙 (영준님 "아미큐 구현 전 설명" = 문서에 완비)

- **시설유형(FCLTY_DIV)**: 단독형=10(마스터만, 대표계기·함내계기수 **비움**, 나머지3개만), 집합형기본=20(함체 첫 마스터그룹), 집합형추가=30(같은함체 2~n번째 그룹, 그룹별 MB_CNT 따로 합산X), 집합형단독=40(단독함체+슬레이브). 함체종류는 데이터에 없어 **작업자 현장지정**.

- **분기기(BUNGI, 슬레이브 전용)**: 없음''/0.5/1/무선(smgw-c=무선).
- **지사→DEPT2**: 동대문중랑3000/광진성동3100/노원도봉3400/서대문은평3500/마포용산3600/강북성북4080. DEPT1=3970 고정. (site-data `지사` 필드 → 구 1:1)

### ★ 사진 첨부 실측 (2026-06-13)
- saveAct를 **FormData**로 호출, 사진은 `ATCH_FILE_ID_{n}_SRC` 키에 **Blob** append (params도 같이 append). `mobCst1000Api.saveAct(formData)`.
- 3MB 노이즈 jpg 통과(고해상도·700KB+ 조건 충족). 
- 응답 = `{result:1, atchFileId3:"F100xxxx", atchFileId4:"F100xxxx"}`. **ATCH_FILE_ID_3, _4 두 슬롯만 응답에 파일ID 반환.**
- **ATCH_FILE_ID_3 = 시공전(마스터, 슬레이브 공유), ATCH_FILE_ID_4 = 모뎀맥(awms 자동공유)** (design §6 일치).
- 3/4/5/6 다 보내도 **응답엔 3/4만** → 시공후1/2(ATCH_5/6)는 응답에 안 나옴. 무시인지 저장만 되는지 미확정(getDetail 키 미상이라 검증 불가). 실제 폼 등록 1건 또는 getDetail 키 확보 필요.

## ★ 영준님 확정 설명 (2026-06-13 — "다 API로, 폼은 파악용")
**아미큐는 awms 폼 안 거치고 전부 saveAct API. 헬퍼가 자동으로 하던 걸 빌더가 코드로.**
- **사진 슬롯**: 마스터 = ATCH 3·4·5·6 다 넣음. 슬레이브 = 3·4·5. 마스터 등록 후 슬레이브 저장 시 **4(모뎀맥)는 awms 자동공유, 3(시공전)은 헬퍼가 마스터 atchFileId3 강제복사**. (앞 실측 응답이 3/4만이던 건 응답키 한정, 실제 3456 다 들어감)
- **통신방식·분기 = 맥+계기번호 조합으로 빌더 계산** (헬퍼 `awms-bridge-inject.js` L1089~1178 이식): `macToSuffix`(E0AEED=10ks-plc/44B433·0014B0=20hpgp/LTE=아미고92·그외70/애매=직접/맥미판별=comm-map.json 폴백), 마스터 INST_S=instM+suffix, 슬레이브=instM+마스터suffix, BUNGI 슬레이브만(smgw-c+아미고=무선/그외0.5). **헬퍼 없으면 직접 입력.**
- **지사·동행시공여부 = 헬퍼 자동**(빌더: 지사→DEPT2, 동행=N). 원래는 매번 수동.
- **봉인**: 설정하면 넣지만 현재 안 함(빈값).
- **신설/기설 구분**: **기설(M1030)** = 기존 설치된 계기+모뎀에 **연결할 때만**. **신설(M1010)** = 새 시설분(슬레이브 새로 다는 것).
- 헬퍼 사진공유 코드: L1164·1283 (마스터 ATCH_FILE_ID_3만 슬레이브 참조복사, ATCH_4는 awms 자동).
- **빌더 추가 자동화 (우리가 강제로 할 수 있는 것)**:
  - **계기번호(INSTR_NUM)**: 수동입력 불필요. **ami-work site-data에서 주소 매칭으로 자동** 취득(계기번호·계기유형 다 site-data에 있음). 작업자는 매칭만.
  - **대표계기(MB_METER_ID)** = 마스터 계기번호 자동.
  - **함내계기수(MB_CNT)** = 마스터 + 슬레이브 수 자동 카운트.
  - → 작업자 입력 최소화 = **모뎀맥 + 사진만**. 나머지(계기정보·통신방식·분기·대표계기·함내수·지사·동행)는 빌더가 site-data+헬퍼로직으로 자동 생성.

## 폼 입력 방식 (파악용 — 실측 2026-06-13)
- **인식 버튼 = QR/바코드 스캔** (`window.AndroidScanner` 네이티브 브릿지, 헬퍼 inject가 scan 호출). 인식 버튼 4개: 대표계기·기존모뎀맥·계기번호·모뎀맥 옆.
- **수기입력 가능**: 계기번호(form0108)·모뎀맥(form010702) = INPUT(스캔+수기 둘다). select(지사/사업명/시설유형/모뎀유형/동행/작업구분).
- **disabled(수기 불가, 스캔/자동 전용)**: 대표계기(form01089)·기존모뎀맥(form010701)·form0104.
- → **아미큐 수집폼 설계**: 작업자 입력 = 모뎀맥 스캔 + 사진 + 시설유형 선택. 계기번호=site-data 주소매칭(또는 스캔). 나머지(대표계기·통신방식·분기·지사·동행·함내수)=빌더 자동.

## 스캔/OCR — awms·Warebiz 서버 의존 없이 자체 구현 (2026-06-13 조사)
- **QR/바코드 스캐너**: 헬퍼 = `GmsBarcodeScanner`(Google ML Kit, QR+CODE128+CODE39, 자동줌). 아미큐 네이티브에 이식. (awms 웹은 ZXing — `research/awms-qr-reader/raw`)
- **QR 변환 법칙** (`awms-bridge-inject.js` L77~581, 완전 규명):
  - `parseValue`: 스캔 raw → {value, value2(제조년월)}. 16개 포맷(11자 바코드 `^\d{11}$`/13자 별표/계기ID/자재ID/제조번호/PID·YYMM·MID/BID/SKT/pcknNo 등).
  - `modemTo012`: LTE 자재ID(G1S3)+8자↑ → `012`+끝8자리. 이미 012면 그대로. **PLC hex MAC(847207D…)은 원본 유지.**
  - `convertForField`: 계기ID/INSTR_NUM/METER_ID/DCU_ID = **변환없음**. 자재ID/MAC/MODEM = **modemTo012**. → 계기는 그대로, 모뎀맥만 012변환.
- **OCR**: awms 원본 = Warebiz **서버 API**(`/ami/mob/emr/api-proxy-warebiz`, 계기 LCD 검침값+계기번호 판독). **우리 학습모델로 대체** (영준님: "이미 트레이닝시킨 애 적용"):
  - 검침값(LCD)=PARSeq(`ocr_poc/run1_seg7.ckpt`), 계기번호=Apple Vision, 검출=YOLOv8/11. EasyOCR 환경(`venv_easyocr`)도 있음.
  - **OCR 판독은 ocr-meter 프로젝트(분리 PM) 소관** [[ocr_project_split]]. 아미큐는 그 모델 **연동**(온디바이스/API).
  - → awms Warebiz 서버 OCR 대체 = 로컬 우리모델, 서버의존 제거.
