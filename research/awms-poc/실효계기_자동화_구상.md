# 실효계기 관리 자동화 구상 (영준님 설명 2026-06-03)

> 상태: **구상 단계 / 미착수**. awms 라이브 쓰기 리스크 + 세션 제약 두 가지 미해결 (아래 FLAG).
> 영준님이 "종로앱 이식 끝낸 뒤 정리"하겠다고 보류한 트랙.

## awms 실효계기 화면 작업 플로우 (영준님 구술)

### 1) 철거 (실효계기 = 완료 안 된 실제 계기)
- 실효계기관리 → **계기추가**
- 완료 안 된 **실제 철거 계기번호** 입력 → **제조년월 자동 입력됨**
- → **지침정보**에 자릿수 + 주간(週) 활성화됨
- **사진**: 촬영/앨범선택/사진보기 탭에서 철거계기 사진 넣음 (앨범선택 정책 = [[photo_upload_policy]])
- **임시저장** 누름 → **임시저장 탭**에 저장됨

### 2) 신설 (부설등록 → 신설계기)
- **부설등록** 누르면 → 신설계기 쪽으로 넘어감
- 신설계기에서 **QR 코드**로 넣으면:
  - 계기번호
  - 계기 실효년도 입력
  - **사진만 넣으면 끝**
- **봉인정보** = 사전설정된 봉인 있으면 **그것 + 1** (추정, 규칙 확인 필요)

## 실행 방식 구상
- 과거 **폰 cron**으로 작업했었음 (핸드폰 자동화 스케줄러)
- 로그인 = OTP라 **한 번밖에 못 함** (영준님 폰 ≠ 작업폰)
- 지금 **브릿지 앱에서 로그인한 세션**으로 작업해야 함
- 그걸 "맥 크롬으로 크론" 시키고 싶다는 구상
- "가상의 자료"로 먼저 테스트 예정

## 미해결 FLAG (착수 전 영준님 판단 필요)

### FLAG 1 — 한전 라이브 awms에 쓰기 (안전)
- "가상 자료 저장" = 한전 운영 awms에 **가짜 데이터를 실제 write**.
- 이번 세션 내내 지킨 원칙 = "**조회만, 저장 금지**". 이걸 뒤집음.
- saveAct/saveRow 흐름은 **캡처조차 실제 write가 발생**해야 잡힘(요청 나간 뒤 recorder 후킹).
- 참고: [[awms_kepco_risk]] (한전 적대 리스크).
- 확인 필요: 테스트(스테이징) 환경 존재? 운영에 가짜데이터 허용/되돌리기 가능?

### FLAG 2 — 맥 크롬 크론은 세션이 없다 (기술)
- awms 세션(OTP 쿠키)은 **폰 WebView 안에만** 있음. 완료받기가 되는 유일한 이유 = same-origin + 폰 쿠키.
- **맥 크롬 = 다른 쿠키 jar → 세션 없음 → OTP 재요구**(불가, 영준님이 한 번뿐이라 함).
- 선택지:
  - (a) 자동화를 **폰에 유지**, 맥은 **adb로 트리거**만 (영준님이 말한 "핸드폰 크론"이 이 방향)
  - (b) 폰→맥 쿠키 export (취약·번거로움)
- 빌드 전 이 부분 먼저 결론내야 헛고생 안 함.
