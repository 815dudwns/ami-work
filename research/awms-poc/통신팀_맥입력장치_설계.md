# 통신팀 맥 입력장치 설계 (맥 로컬서버 + 폰 아미큐 분리)

> 2026-06-30 영준님과 설계 확정. 기존 [[통신팀_설비등록_조사]](아미큐 단독 재빌드)를 **맥 로컬서버 + 폰 분리** 아키텍처로 진화시킨 상위 설계.
> 통신팀 awms = MOBCST `mob/cst`. 계기팀(mob/mtr)과 별개 — 교차호출 405.

## 왜 이 구조인가 (영준님 동기)
- 폰 앱(아미큐)으로 awms 입력 시 **딜레이가 길다**: webview freeze(가시성) + 네이티브 변경 시 APK 빌드 사이클.
- 맥 백엔드가 awms에 직접 올리면 그 딜레이가 통째로 사라짐 — 키보드로 폼 채우고 엔터, 백엔드가 바로 등록 ("오프라인처럼 자연스럽게").

## 역할 분담 (확정)
| 구성 | 역할 |
|---|---|
| **폰 (아미큐 개조)** | ①통신팀 OTP 로그인 → awms 세션(JSESSIONID) 발급·보유 ②현장 사진 → 맥 로컬서버로 전송 ③세션을 맥서버에 공유 ④**맥 다운·직접호출 막힐 시 awms 직접 업로드 폴백** |
| **맥 로컬서버 (FastAPI, 검증포털 8765 패턴)** | ①폰에서 사진·세션 수신 ②브라우저 키보드 폼 입력(모뎀 설치 정보) ③맥 로컬 디스크 사진보관 + 건별 큐 ④EXIF 미세보정 ⑤거의 즉각 `saveAct` 직접 등록 |
| **터널 상시 (cloudflared 등)** | 현장 셀룰러 폰 ↔ 사무실 맥 연결. 검증포털 방식 재사용. 즉각 업로드 위해 항상 켜둠 |

## 핵심: 세션 핸드오프
- 폰에서 OTP 로그인으로 발급된 JSESSIONID를 맥이 넘겨받아, 맥 백엔드가 그 쿠키로 awms API 직접 호출.
- 쿠키 추출: CDP(`cdp_eval.py document.cookie`) 또는 네이티브 CookieManager(httpOnly 대비).
- **세션 ~4시간 만료** — 단 영준님: "밤 분산 업로드 없음, 거의 즉각" → 작업 직후 발사라 만료 거의 비이슈. 그래도 스케줄러는 **발사 직전 세션 생존 체크 → 죽었으면 조용히 실패 말고 폰 OTP 재인증 요청**(안전장치).

## 사진 보관 = 맥 로컬 (Firebase 안 씀)
- 흐름: 폰(현장, 셀룰러) → 터널 → 맥 로컬서버 디스크 → awms saveAct.
- Firebase Storage 경유는 폰→FB→맥→awms 클라우드 왕복 2번. 맥 로컬은 왕복 0, awms 올릴 때만 외부. **더 빠름.**
- 용량: 건당 사진 3~4장 × 700KB ≈ 2~3MB. 하루 수백건도 GB 단위, 맥 SSD 충분.
- 큐 유실 걱정 없음 — **맥 다운 시 폰 헬퍼/아미큐로 awms 직접 업로드 폴백**이 증거 안전망. (그래도 큐 폴더 주기 백업 권장. [[firebase_storage_no_autodelete]])

## EXIF 미세보정 (아미맵 방식, 감사용 화장)
- **awms는 사진 시각을 검증하지 않음** (해상도 2992px+ / 700KB+ / ICC없음만 체크). 시공전/후 구분은 EXIF 순서가 아니라 **슬롯**(ATCH_FILE_ID_3 시공전 / 5·6 시공후)으로 판별.
- 즉 EXIF 시프트는 awms 통과조건이 아니라, 나중에 사람이 사진 볼 때 시각이 작업시각과 자연스럽게 맞게 보이는 **감사용**. **크리티컬 패스 아님(저위험)**.
- 방식: ami-work `admin.html`(piexifjs) — 마지막 사진을 **유저 지정 작업시각**에 고정, 나머지는 상대간격 유지하며 일괄 시프트. 변경필드 DateTimeOriginal/DateTime/DateTimeDigitized. 맥 백엔드는 piexif/exiftool **메타 전용**(픽셀 재인코딩 금지 → 해상도·크기 유지로 awms 게이트 충족).

## saveAct 페이로드 (상세는 [[통신팀_설비등록_조사]] + awms_API_레퍼런스 §6)
- `POST /ami/mob/cst/mobCst1000/saveAct`, WORK_STEP=28(통신팀은 임시저장25 없이 saveAct가 곧 완료).
- 필수: DEPT1=3970, DEPT2=7793, WORK_DIV=M1010, FLAG=M10, MTR_WITH_YN=Y, FCLTY_DIV, MODEM_DIV(10마스터/20슬레이브), INSTR_NUM, INST_M/INST_S, MAC_MODEM, MB_METER_ID, MB_CNT, BUSI_NUM, BUNGI(슬레이브).
- 마스터/슬레이브 = 같은 MAC_MODEM 2행. 사진 FormData(ATCH_FILE_ID_{3,4,5,6}_SRC).

## ★ PoC 실측 결과 = 성공 (2026-07-01, 맥 직접 호출 확정)
- **환경**: A33 폰 USB, 헬퍼(com.youngjun.awmshelper PID 7978) webview에 awms portal_main, 통신팀 계정 273584(우영준). 폰 셀룰러(맥과 다른 IP).
- **세션 추출**: JSESSIONID는 **httpOnly** → `document.cookie` 불가. `cdp_cookies.py`(신규, CDP `Network.getAllCookies`)로 추출. forward = `adb forward tcp:9222 localabstract:webview_devtools_remote_<헬퍼PID>`. 단 webview 백그라운드면 fetch freeze → 헬퍼를 포그라운드+화면ON(`monkey -p ... LAUNCHER`, keyevent 224) 후 동작.
- **읽기**: 맥 curl `getBusiList` → **HTTP 200 JSON** (폰 UA·쿠키·Referer 첨부). 다른 IP에서 세션 인식 OK.
- **쓰기**: 맥 curl `saveAct` 더미 → **HTTP 500 CODE:631 NOT NULL** = **차단 아님**. awms가 요청 받아 SQL INSERT까지 시도 = **세션·IP·UA·CSRF 전부 통과**. 631은 필드 부족(트랜잭션 롤백=미등록).
- **결론**: 맥 세션 직접 호출 **기술 확정**. "맥이 알아서 올린다" 성립.
- **★ saveAct result:1 맥 직접 등록 성공** (더미 09990000088, 사진 1x1 4장): 631 NOT NULL 범인 = **`DANGER_INFO_FLAG=2` + `MODEM_MAC`(MAC_MODEM과 별개)** 누락이었음. 이 둘 채우니 result:1.
- **정본 페이로드 = `통신팀_saveact_정본.json`** (UI 완료 실캡처): 마스터 80필드 / 슬레이브 52필드. 본구현 빌더의 기준값.
  - 마스터: 사진 ATCH_FILE_ID_3/4/5/6_SRC 4장(Blob), MB_CNT=함내수, MB_METER_ID=자기, MODEM_DIV=10.
  - **슬레이브: 사진 공유 = ATCH_FILE_ID_3/4에 마스터 응답 파일ID(F100…) 문자열로 넣음, 고유사진은 ATCH_FILE_ID_5_SRC만 Blob.** MODEM_DIV=20, BUNGI=무선(smgw-c), MB_METER_ID=마스터계기. (`__a3tried=true`는 헬퍼 inject 흔적, 무관)
  - 공통 필수: ROW_TYPE=2, FILTER_ROW=N, DANGER_INFO_FLAG=2, MODEM_MAC, WORKER1/2_SEQ(공사설정값), GUBUN=01, DCU_SIGONG_CD=N, TDU_USE_YN=N, mbInsertCnt=0, ERR_LIST=[], SEAL_UPD=N.
- **공사설정(menu=01040000)**: 작업자1/2·공사번호(BUSI_NUM)를 세팅하는 곳(계기큐 봉인설정 격). saveAct의 WORKER1_SEQ=273584·WORKER2_SEQ=20118·BUSI_NUM=C11G250023가 여기서 옴. **본구현은 이 설정 조회 API로 자동 반영해야**(영준님 지시).
- **deleteRows**: JSON 배열 POST지만 **XSRF-TOKEN 쿠키 + X-XSRF-TOKEN 헤더 필요** → 맥 curl(헤더 없음)은 HTML 500. 정리는 폰 `mobCst1000Api.deleteRows(행배열)`로 성공(data:1). 행에 `DANGER_INFO_SEQ` 포함. **맥 직접 deleteRows 하려면 XSRF 토큰도 cdp_cookies로 추출해 헤더 첨부.** (saveAct는 FormData라 XSRF 불요)
- **통신팀 getMainList 파라미터**: `FLAG=M10&DEPT1=3970&DEPT2=7793&searchKeyword=&sortKey=0&workStep=25,28&pPageNo=1&pRowCount=N&strDate=YYYYMMDD&endDate=YYYYMMDD` (계기팀과 달리 strDate/endDate 필수, 없으면 CODE:176 date format).
- **신규 스크립트**: `cdp_cookies.py`(httpOnly 세션 추출, Network.getAllCookies) / `cdp_saveact_body.py`(UI 완료 saveAct multipart body 강제 캡처, base64 디코드 필요).
- **읽기(getBusiList) 200은 false green** — 한전 계열은 쓰기에만 CSRF·UA·referer 보호를 거는 경우 흔함. 반드시 쓰기로 테스트.
- **폰을 셀룰러로 돌린 상태**에서 맥 curl. 같은 wifi면 폰·맥 공인IP 동일 → IP바인딩 있어도 통과해버려 무의미. 프로덕션은 폰=셀룰러/맥=사무실로 항상 다른 IP.
- 더미계기 `09990000006`로 saveAct → result:1 확인 후 deleteRows 정리.
- **결과 분기**: result:1 → 맥 직접호출 확정(빠름). 거부 → **폰 전송 폴백**(폰 세션·폰 IP라 무조건 통과, 맥은 입력 UI만). **PoC 실패해도 설계 안 무너짐** — 폰앱↔맥서버 연결이 이미 깔려있어 전송 주체만 폰으로 바꾸면 끝.

## 본구현 UI 플로우 (영준님 확정 2026-07-01)
1. **로그인(가짜)** — 맥 입력장치 자체 로그인 → awms 세션 확보 + **카톡 OTP 자동수집(헬퍼 메커니즘)**. awms 실로그인/OTP는 폰 헬퍼가 처리, 맥은 세션(JSESSIONID+XSRF) 넘겨받음.
2. **사진 수집** — 마스터 3(작업전)/4(모뎀맥)/5(계기)/6(집합) 4장 + 슬레이브 N개(각 5번 계기사진, N장=슬레이브 N개).
3. **[사진 넘김=다음]** → 즉시 **AppleVision OCR 백그라운드 시작**(5번 계기사진들 계기번호 선추출). 사진을 먼저 보내야 OCR이 먼저 도므로 순서 중요.
4. **모뎀맥 수집** — QR/바코드 스캔(헬퍼 스캐너 참조). OCR과 **병렬**. 사진 넘긴 직후 맥 받음.
5. **계기번호 확인** — 마스터→슬레이브 순. 5번 계기사진 보여주며 텍스트박스에 OCR값 자동입력 → **맞으면 다음 / QR 인식 / 수기 직접입력(지우고)** 3경로.
6. **나머지 필드 = 헬퍼식 자동·설정**: 통신방식(INST_S=INST_M+suffix, 모뎀맥 hex→suffix 자동판별 macToSuffix) / 지사(DEPT2 매핑) / 동행시공여부(설정).
7. → **saveAct**(마스터+슬레이브 결합, 대표계기 MB_METER_ID 자동, 슬레이브 사진 3/4=마스터 파일ID 공유).

**헬퍼 참조원**: 통신방식/지사/동행 자동 = `awms-bridge-inject.js` L1089~1178(macToSuffix). QR/바코드 = 헬퍼 `AndroidScanner.scan` + [[awms_scanner_extracted]](ZXing/parseValue, research/awms-qr-reader/).

**재사용 자산**: OCR=ocr-meter `visionocr_batch.swift`(swift 배치, 이미지리스트→텍스트) + daily_cycle.py:708 `run_meter_id` 패턴 / FastAPI=admin-validation `backend/app.py`(포트 분리, no-cache 정적, start.sh) / 폼=ami-queue-www `collect.js`(마스터4슬롯·슬레이브N, FileReader base64, 드래그reorder).

## 빌드 두 갈래 (병렬 가능)
- **A. 맥쪽 골격** (전송방식 무관, 바로 착수): FastAPI + 브라우저 폼 UI + 맥 로컬 사진보관 + 큐 + EXIF + 즉각 스케줄러.
- **B. 폰 아미큐 개조**: 사진→맥서버 전송 + 세션 공유 + 헬퍼 직접업로드 폴백. + 전송 PoC.
