# 데이터관리자 플랜 — 아미큐를 대신할 맥 입력장치 (2026-07-17)

> Base design (authoritative): `통신팀_맥입력장치_설계.md` (confirmed with 영준님 2026-06-30, PoC passed 2026-07-01).
> This plan = gap between that design and today's codebase + **direction correction**.

## ★ Direction correction (영준님 2026-07-17)

Previous half-built attempt went BACKWARDS: it was a viewer that syncs/displays what the
phone (아미큐) uploaded. That is NOT the 데이터관리자.

**Correct direction (= original 6/30 design):**
- **Mac = input device.** Office operator types/confirms on the mac form; mac local server
  (cst-input backend, 8766) registers to awms directly (saveAct) with the handed-off session.
- **Phone (아미큐) = OTP login/session issuance + field photo transfer + fallback uploader only.**
- Viewing/monitoring what was registered is a byproduct (verify/getMainList), not the product.

## What already exists (reuse, don't rebuild)

Backend `cst-input/backend/app.py` (8766, live as 아미큐's backend today):
- `/api/session` pull/push (JSESSIONID handoff from phone)
- `/api/ocr` (meter-id OCR), `/api/bdju` (변대주 DATA_NUM lookup)
- `/api/saveact` + `/api/saveact/stream` (master/slave builder, EXIF, photo slots)
- `/api/verify` (getMainList re-query = registration confirmed)
- `/api/config` (DEPT2/WORKER/BUSI_NUM etc.)

Web form skeleton `cst-input/www/` (index.html + collect.js + settings.js) — originally the
phone webview form, unused by the native app since v2.1.6. Good skeleton for the mac UI
(btnSubmit → backend saveAct path already wired).

Design doc §본구현 UI 플로우 (7 steps, confirmed 7/1):
login(session handoff+OTP) → photo intake(master 4 + slave N) → AppleVision OCR pre-extract
(background, starts on photo hand-off) → modem MAC scan (parallel) → meter-id confirm
(OCR autofill / QR / manual) → auto fields (comm-type macToSuffix, DEPT2, 동행) → saveAct.

## Gap = the mac UI (데이터관리자 화면)

1. **Photo intake from phone**: 아미큐에 "맥으로 보내기" 경로(사진+메타 전송) 또는 기존 큐
   데이터를 맥이 받는 endpoint. (아미큐 개조 범위는 최소 — 전송 1버튼)
2. **Mac input screen** (www/ 개편): keyboard-first form, photo pane + OCR autofill +
   meter-id confirm flow, master/slave group model (맥이키), queue list with per-item state
   (대기→등록중→verified), local disk photo store.
3. **Session watchdog**: fire-time session check → dead → request phone OTP re-auth
   (already designed; backend has session push/pull).
4. **공사설정(menu=01040000) auto-fetch** — WORKER1/2_SEQ·BUSI_NUM from awms instead of
   manual config (design doc TODO, backend L75 comment).
