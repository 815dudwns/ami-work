# ami 사진등록 → DataPush 개편 설계 (영준님 요구사항)

목적: ami-work 사진등록 시스템을 개편 → 작업자가 사진+데이터를 모아 **awms 임의추가(임시저장)에 자동 매핑**하는 DataPush로.
(awms 자동화의 입력 소스. 완료/슬래이브 추가는 영준님 수동. 로그 쌓이면 API 완성)

## UI 변경
- **X 버튼**: 지도로 돌아가지 말고 → **리스트가 있는 창으로** 복귀
- **관리자 화면(admin.html)**: 현행 유지. **사진 시간 바꾸는 작업만** 유지
- **리스트 화면의 "사진등록" → "DataPush"** 로 명칭/기능 변경

## DataPush = awms 임의추가 필드 채우기

### 헤더 필드
| 필드 | 값/규칙 |
|------|---------|
| 지사 | 서울지역본부 주로. **결정 기준 조사 필요** (어떤 데이터로 지사 가져오는지) |
| 시설유형 | 아래 4종 |
| 모뎀유형 | 자동 결정 (마스터/슬래이브 결정하는 것) |
| 대표계기 | 첫 번째 계기(마스터)의 계기번호 |
| 함내계기수 | 그 주소 **함체 내** 계기수 = 마스터 + 슬래이브 총개수 |
| 동행시공여부 | ami-work = **N** / 종로앱 = **Y** |

### 시설유형 4종 (영준님 확정 2026-06-08) — 함체 종류 + 함체 내 마스터순서
함체 종류 2가지가 1차 기준:
- **단독형 함체**: 집 설계 때 함체를 못 넣어서, 나중에 **벽에 개별 함을 따로 달아** 계기 설치 (보통 그 계기 하나)
- **집합형 함체**: 설계 때 **함체를 매입**해 만든 함 (여러 계기 모임)

| 시설유형 | 코드(FCLTY_DIV) | 함체 | 상황 |
|---|---|---|---|
| **단독형** | 10 | 단독형 함체 | 마스터만 (슬래이브 없음). **대표계기·함내계기수 비움**, 나머지 3개만 채움 |
| **집합형단독** | 40 | 단독형 함체 | 단독 함체인데 **슬래이브까지** 닮 (미사용 아님 — 우리는 씀) |
| **집합형기본** | 20 | 집합형 함체 | 함체의 **첫 마스터그룹** (계기 1개여도 집합함체면 이것) |
| **집합형추가** | 30 | 집합형 함체 | **같은 함체의 2~n번째 마스터그룹** |

**판정 핵심 = 함체 경계**:
- 같은 함체 안 마스터 2개 → 첫째 **기본(20)** + 둘째 **추가(30)**
- **다른 함체** 2개 → 각 함체 첫 마스터 = **기본(20) + 기본(20)** (추가 아님). 함체 2개 = 집합형기본 2개.
- 함체 종류(단독/집합)는 데이터에 없음 → **작업자가 현장에서 지정**. 슬래이브 없는 마스터가 단독함체인지 집합함체-계기1개인지 데이터로 구분 불가.

### 함체 개념 (중요)
- 한 주소에 계기 5개 → 한 함체에 다 있을 수도, 함체 2~3개로 나뉠 수도
- **함내계기수(MB_CNT) = 그 함체(그룹)의 마스터 + 슬래이브 수** (주소 전체 합산 아님)
  - 집합형추가도 **그룹별 따로**: 함체A 4개→그 마스터행 4, 함체B 5개→5 (4+5=9 합산 X)
- **단독형(10)은 대표계기(MB_METER_ID)·함내계기수(MB_CNT) 둘 다 비움**
- **수집 모달 = 함체 단위 묶음**. 단독형(마스터1·슬래이브0)을 디폴트로 깔아 입력 최소화(보통 모뎀맥+사진만).

## 사진 4종
| 사진 | 내용 | 공유 범위 |
|------|------|-----------|
| 시공전 | 시공 전 **함체 내 모든 계기** 사진 | 마스터+할당 슬래이브 **동일 사진** |
| 모뎀맥 | 모뎀맥 적힌 곳 **크게** 찍은 사진 | 마스터+할당 슬래이브 **동일 사진** |
| 시공후1 | **해당 계기** 사진 | 계기별 개별 |
| 시공후2 | 시공 후 **함체 내 모든 계기** 사진 | 계기별 개별(시공후) |
- 모든 계기(사진)에 시공전/모뎀맥/시공후 다 들어감
- 시공전·모뎀맥 = 마스터와 그에 할당된 슬래이브가 같은 사진 공유
- 시공후 = 각 계기의 시공후 사진

## 계기별 필드
| 필드 | 규칙 |
|------|------|
| 계기번호 | 그대로 |
| 모뎀맥 | 그대로 |
| 계기유형 | 계기번호 넣으면 자동 채워짐 |
| 통신방식 | 계기번호 넣으면 활성화. 아래 5종 |
| 분기기 | **슬래이브일 때만** 활성화. 없음/0.5/1/무선 |
| 외장형 연결장치 | Y / N |
| etype | 모뎀을 AE타입에 쓸 수 있게 |
| 변대주 | 맥이 PLC/K-DCU일 때 변대주 정보 (ami-work 변대주 복사버튼 값) |
| 작업구분 | 대부분 신설 / 기설 |

### 통신방식 5종
- **ks-plc**: 1~4차 DCU와 통신
- **hpgp**: HPGP DCU와 통신
- **lte_IV**: DCU 아닌 LTE로 직접 통신
- **k-dcu**: 5-1/5-2/6차 DCU 통신 (= iot-plc)
- **smgw-c**: 아미고 LTE 모뎀

### 분기기 (슬래이브 전용)
- 무선 = 아미고 모뎀 끼리 통신 (아미고 모뎀 꽂았을 때)
- 나머지 = **0.5로 통일**

### 작업구분
- **신설**: 대부분
- **기설**: 기존 모뎀 설치된 계기에 마스터 잡고 대상계기를 슬래이브로. 그 마스터 계기 정보 넣고 기설로.
  - 이때 영준님이 ami-work에서 **기설 마스터를 계기추가**함

### etype 특이사항
- iot-plc에 etype 모뎀 재고 많음 → **연결장치 연결해 AE타입에 시공**하는 게 대부분
- 나머진 안 건드림

## awms saveAct 필드 매핑 (조사 완료) — `POST /ami/mob/cst/mobCst1000/saveAct`
| 요구값 | awms 필드 | 코드 |
|---|---|---|
| 시설유형 단독/집합기본/집합추가/집합단독 | FCLTY_DIV (CST007) | 10/20/30/40 |
| 모뎀유형 마스터/슬래이브 | MODEM_DIV (CST008) | 10/20 |
| 계기유형(자동) 표준/E/G/Adv-E/AMIGO | INST_M | HW4010/4020/4030/4040/4050 |
| 통신방식 (INST_S = INST_M prefix + suffix) | INST_S | suffix 10=ks-plc·20=hpgp·70=lte_IV·80=iot-plc·90=k-dcu·92=smgw-c |
| 분기기 없음/0.5/1/무선 (슬래이브만) | BUNGI (CST019) | ''/0.5/1/무선 |
| 외장형 연결장치 (HW4040일때만) | EXT_CONN_DEV | Y/N |
| 작업구분 신설/기설 | WORK_DIV (M10) | M1010/M1030 |
| 동행시공여부 (ami=N) | MTR_WITH_YN (CST029) | N/Y |
| 대표계기(마스터 계기번호) | MB_METER_ID | 계기번호 |
| 함내계기수(마스터+슬래이브) | MB_CNT | 정수 |
| 신규 계기번호 | INSTR_NUM | 계기번호 |
| 모뎀맥 | MAC_MODEM | 맥값 |
- 통신방식 = INST_M(계기유형, 계기번호로 자동) + 통신방식 suffix 조합. 예: AMIGO+smgw-c = HW405092
- 지사 DEPT2 select = MOBCST1000.html:910. content.js BASE_FIELDS는 7793 고정이라 DataPush에서 지사별로 채워야 함.

## 남은 미해결 (실제 saveAct 1회 캡처로 해결 가능 — recorder)
1. **etype (모뎀을 AE타입에)**: 전용 필드 없음. INST_M=HW4040(Adv-E)+EXT_CONN_DEV=Y 조합 **추정, 미검증**. → 영준님이 awms에서 실제 etype/AE 임의추가 1건 저장하면 recorder가 saveAct payload 잡아 확정.
2. **변대주(PLC/K-DCU 시)** 들어갈 필드: EXT_DCU_ID/EXT_DCU_MAC/NEW_DCU_MAC/DCU_ID 후보, 미확정. → 동일하게 실제 PLC 건 saveAct 캡처로 확인.
3. **수집 단위**: 함체(마스터1+슬래이브N) 묶음. 마스터 다수면 그룹 여러개.

## DataPush UI 인터랙션 모델 (영준님 확정)
### 자동 수집 (detail/site-data에 이미 있음 — 수집 불필요)
- 지사, 동행시공여부(ami=N), 계기번호, 계기유형(계기번호로 자동)

### 수동 수집 (DataPush 창)
- **사진 4종**: 1=시공전 / 2=모뎀맥 / 3=시공후1 / 4=시공후2 — 업로드 후 계기에 할당
- **모뎀맥**: 입력(QR스캔) → 통신방식 자동 판별
- **마스터/슬래이브 = 사진 할당 패턴으로 자동 판별** (작업자가 따로 안 고름):
  - 1,2,3,4 **전부 할당** = 마스터
  - **하나씩만** 할당 = 슬래이브 (시공전·모뎀맥은 그 마스터 사진 공유)
- **마스터 2개 이상**: 계기 행을 **드래그**해 각 마스터 그룹에 배치. 마스터마다 1,2,3,4 가지고, 그 아래 계기들이 해당 마스터의 슬래이브.

### 자동결정 체인 (입력 최소화)
- 계기번호 → **계기유형**(자동)
- 모뎀맥(QR/바코드 스캔, 모뎀맥 사진칸 밑) → **통신방식 결정 (맥 prefix로 판별)**
  맥 prefix → 통신방식 (보강현황 전체행=숨김포함 분석, 잠정 — 전수/교차검증 진행 중):
  - `847207` + 7번째 **0 또는 E** → **k-dcu** (iot-plc) [13866 + 1244]
  - `847207` + 7번째 **B/C/D** → **ks-plc** (awms 라벨 "PLC") [3741+]
  - `44B433*`, `0014B05*` (hex MAC) → **hpgp** [3917+273]
  - 16자리 숫자 `050404/0504*/0505*` → **lte_IV**
  - 16자리 숫자 `343835/343836/040908/040907` → **smgw-c** (아미고)
  - ※ D/E만이 아님 주의. 판별은 847207 7번째글자 + 별도 vendor prefix 조합
  - ※※ **중요**: 위는 엑셀(awms 내부) 맥 표기. 실제 스캔값(vBarcdQr)은 형태가 다름:
    - **`012...` 11자리 숫자 (예 `01249852054`) = lte_IV / smgw-c(아미고)** — LTE 계열 [영준님 확인]
    - DCU 계열(ks-plc/k-dcu/hpgp) 스캔값 형태 = 확인 중 (recorder에 075/085 prefix도 보임)
  - **DCU ID 끝 2자리** = DCU 계열 3종(k-dcu/ks-plc/hpgp) 구분 단서 [영준님]. lte_IV/smgw-c는 DCU 없음.
  - **통신방식 판별 규칙 (보강현황 0528 전수: 맥 col20 + DCU ID col15 + 통신방식 col17)**:
    | 통신방식 | 판별 (우선순위순) | 순도 |
    |---|---|---|
    | **K-DCU**(iot-plc) | DCU ID 끝2 = `5M/5S/6M/6S` (5·6차) **또는** 맥 `847207[0/E]`·`AC5E8C` | DCU끝 ~100% |
    | **HPGP** | 맥 `44B433`·`0014B0` | 97~98% |
    | **ks-plc** | 맥 `E0AEED`·`847207[B/C/D]` (DCU 끝 1~4차 숫자) | 96% |
    | **lte_IV** | 맥 `012...` 숫자11 / DCU 숫자 / `LTEDCUSU01` | — |
    | **smgw-c**(아미고) | 맥 `012...` 숫자11 / DCU `47640008502`(11자리) | lte_IV와 구분 별도 |
    - 핵심: **DCU ID 끝2자리 M/S(5M/5S/6M/6S) = K-DCU(5·6차 마스터/슬래이브)**, 숫자끝 = 1~4차(ks-plc/hpgp). hex 맥 prefix가 ks-plc/hpgp/k-dcu 직접 판별.
    - **HPGP vs ks-plc 세부**: 맥 hex(44B433/0014B0=HPGP, E0AEED/847207[BCD]=ks-plc) 확실. **DCU끝2 `41`/`45`=HPGP 고유**, `44/00/01/29/30/20/31`=ks-plc. **`39`+숫자맥은 구분 불가**(DCU끝3·사업차수·맥 전부 겹침) → site-data 통신방식/작업자 확인.
    - 사업차수: HPGP는 3·4차만(1·2차 거의 0), ks-plc는 1~4차 전부.
  - **`39`+숫자맥 겹침 규모**: 전체 PLC+HPGP 86,280건 중 12,372건(14.3%) 구분 불가 (그 중 PLC 77%/HPGP 23%).
  - **시공 시 통신방식 변경 가능 (영준님)**: **DCU 있어도 LTE 설치 가능** → site-data 기존 통신방식 ≠ 실제 설치값. site-data는 **추천값**, 최종은 영준님이 detail+소스 보고 결정.

## 통신방식 자동화 = 작업 로그 축적 (핵심 철학)
- **진짜 문제**: 스캔한 모뎀맥 → 통신방식 **자동 저장(매핑)**. 이것만 되면 나머지(계기/사진/지사/마스터·슬래이브) 다 있어 awms 매핑 완성.
- 맥 100% 자동판별은 현재 불가(14% 겹침 + DCU여도 LTE 가능).
- **해결**: DataPush에서 영준님이 모뎀 스캔 + 통신방식 확인 → **맥↔통신방식 매핑 로그 축적** → 누적되면 맥 패턴 정확해져 자동 판별. (recorder "로그 쌓이면 API 완성"과 동일)
- **영준님이 남기는 작업 로그를 보고 자동화 로직 구축**.
    - **숫자맥(3438/0504/0409)은 전 통신방식 공통 = 판별 불가** → hex맥 + DCU끝2자리로 판별해야.
    - selectMtrlUseYn 응답엔 통신방식 없음(awms 검색으로 못 받음). 실제 스캔값(vBarcdQr)은 012 LTE만 샘플 있음.
