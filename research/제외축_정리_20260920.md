# 제외축 정리 — 25년 미청구 · 25년 미청구불가 (2026-09-20)

> 영준님 "제외된 사유 리스트 잘 관리해". **왜 빠졌나를 SQL 한 줄로 답하는 자리**다.
> 하루 만에 축이 6개에서 8개로 늘었고 제외분 파일이 7개로 흩어졌다. 스키마가 제각각이라
> 한 계기를 되짚으려면 파일 7개를 열어야 했고, 한 건이 두 축에 걸리는 일도 실제로 나왔다.

## 0. 어디를 보면 되나

| 쓰임 | 위치 |
|---|---|
| **조회** | `python3 scripts/why_excluded.py <계기번호>` · `--cust <고객번호>` · `--rule <축코드>` · `--summary` |
| 제외 이력 (정본) | `data/exclusions.json` — 계기 단위, 통일 스키마. **원본 레코드·원장 행을 통째로** 담는다(52MB) |
| 제외 이력 (사본) | `ami.db :: exclusions` — SQL 조회용 |
| 축 정의 (정본) | `scripts/exclusions.py` 의 `RULES` → `data/exclusion_rules.json` · `ami.db :: exclusion_rules` |
| 재생성 | `python3 scripts/build_exclusions_index.py` (검증 리포트까지 같이 찍는다) |
| 원본 제외분 | `research/*제외*.json` — **지우지 않는다**(감사 흔적). 인덱스가 흡수한다 |

## 1. 스키마

### `exclusions` (계기 단위)
```
계기번호 · 계기번호_norm · 고객번호 · 지사 · 주소        ← 조회용으로 펼친 열
원본리스트(25미청구|25년불가) · 축코드 · 축이름
사유          ← **사람이 읽는 문장**. 무엇과 무엇을 비교해 걸렸는지가 재구성된다
판정근거 · 판정방법 · 되살리기 · 지시근거
제외일자 · 제외시각 · 빌더버전                              ← 언제 판정한 것이냐
원본      { 제외 시점 레코드 **전체** — 필드를 고르지 않는다 }
원장원본  [ 그 계기의 원장 행 **전부** — 우리 리스트에 없는 정보가 거기 있다
            (상태·공종·구분·비고). 열 이름이 비어 col_15 로 들어간 것도 그대로 둔다 ]
```
★**한 건이 여러 축에 걸리면 행을 나눠 전부 남긴다.** 빌더는 첫 축에서 멈추지만(총합이 어긋나지
않게) 기록은 전부 있어야 한 축을 되살릴 때 "다른 축에도 걸려 있으니 되살리면 안 된다"를 안다.
현재 **72건**이 두 축에 걸려 있다(전부 25미청구 M1+M3 = 고압인데 26년에도 시공된 개소).

### `exclusion_rules` (축 정의)
```
축코드 · 대상리스트 · 축이름 · 정의 · 판정방법 · 적용순서 · 근거 · 되살리는법 · 공용함수명 · 현재건수
```

## 3. 재현할 때 걸렸던 것 (다음 사람이 또 밟지 않게)

- **원장 테이블은 `20260227다운로드_2025_03_24에서2026_0` 이다.**
  이름만 보면 `25년_ami_보강공사_미청구2__sheet1`(258,394) 이 원장 같지만 그건 **작업중 시트**라
  상태 열이 없다. 거기서 찾다가 모집단이 0 으로 나왔다.
  상태 열은 엑셀 O열인데 **헤더가 비어 있어 `col_15` 로 적재**됐다. `col_15='미청구'` 고유계기 = 13,182.
- **고압 판정은 계기 단위다** — 그 계기의 **어느 행에든** 공종=고압이 있으면 고압이다.
  미청구 행만 보면 2건을 놓친다(29450242649 봉익동 · 74450062896 중곡동 — 원장에 4행씩 있고
  고압(불가) 행과 미청구 행이 섞여 있다). 이 2건 때문에 재현이 635 로 나와 PM 표 637 과 어긋났다.
- **번호 교정분은 제외가 아니다.** `METER_TYPO_FIX` 2건(3919048106A→39190481064 ·
  4719B160548→47198160548)은 모집단엔 오타본, 리스트엔 교정본이 있다. 제외 인덱스에 넣으면
  '빠졌다' 는 오해를 주므로 **대조할 때만 키를 맞춘다**.

## 3.5 확인 완료 사실 (다시 묻지 않게)

- **25년불가 리스트는 26년 `modem_work_all` 과 한 건도 안 겹친다.**
  계기번호 직접 · 고객번호 경유(원장) · 보강현황 경유 — **셋 다 0건**이다(2026-09-21 실측).
  겹침이 있는 것은 **25년 청구**(B6 축)이지 26년 시공이 아니다.
- **기설 계열 1,058건은 원장에서 거의 전부 '불가' 다**(불가 1,056 · 미청구 2).
  그리고 **고객번호 경유로 원장 '청구' 계기가 있는 건은 0** 이다 —
  즉 현장이 말하는 '기설치' 는 **우리 원장 밖에서 처리된 것**이다. 우리 청구 이력과 무관하다.
- 28건 전량 분석 = `research/불가_25청구겹침_28건분석_20260921.txt`.
  그중 7건만 뺐다(B6). 나머지 21건은 근거 부족이라 남겼다 —
  기계식 4 · 문잠김/주차 5 · 계기못찾음 8 · 기타 4.

## 4. 앞으로

빌더가 제외할 때마다 `EX.stage()` 로 스스로 기록한다(`data/.exclusions-stage/`).
**축이 새로 생겨도 사람이 파일을 만들 필요가 없다.** 빌더를 돌린 뒤
`python3 scripts/build_exclusions_index.py` 를 돌리면 인덱스가 갱신되고 모집단 대조까지 찍힌다.
빌더 **밖**에서 걸러지는 축(고압·Sheet2·26년보강시공·미연계·사유분류·중복)은 그 스크립트가
원장·DB 로 재현한다 — 원본이 DB 에 다 있어 언제든 다시 만들 수 있다.
