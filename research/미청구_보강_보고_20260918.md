## 3. DCU → 변대주 역산과 검증

`dcu_all` 19,007건 전수 확인: **DCU ID(10자) = 변대주번호(8자) + 2자리** (19,007/19,007 일치).

| 역산 | 건수 |
|---|---:|
| 변대주번호 → DCU ID (대장) | 2,342 |
| 변대주번호 → 변대주명 (대장) | 2,289 |
| DCU ID → 변대주번호 (대장 확인) | 2,168 |
| 변대주명 → 변대주번호 (지사+이름, 대장) | 152 |
| DCU ID → 변대주번호 (법칙 앞 8자리만, **대장에 없음**) | 130 |
| 교정: 원장 변대주가 대장 미등재 → DCU 대장값으로 대체 | 101 |

**검증 방법**: 채운 뒤 `DCU_ID[:8] == 변대주번호` 를 전건 대조했다.
- 1차 산출에서 **792건 불일치** → 원인은 규칙 위반이 아니라 **내 정규화 버그**였다(아래 §5).
- 정규화를 고치고 교정 규칙을 넣은 뒤 **132건**이 남는다. 이 132건은 둘 다 `dcu_all` 에
  실재하는 값으로, **교체 전 DCU(원장 기존변대주) ↔ 교체 후 DCU(보강현황)** 가 갈린 정상 케이스다.
  영준님 2026-09-09 지침("DCU ID 는 옛 소속을 가리킬 수 있다 → **변대주 우선**")대로
  **변대주 쪽을 남겼고**, 레코드에 `변대주_대장확인`·`DCU_대장확인` 플래그를 붙였다.
- 대장 확인율: 변대주번호 보유 9,284 중 **7,235 대장 확인** / DCU ID 보유 7,406 중 **7,158 대장 확인**.

성격 — **왜 어떤 소스에도 안 걸렸는지가 설명된다.**
- **공종**: 빈값 2,474 · 고압 171 · 25년 보강 79
- **구분**: 기설 1,844 · 신설 603 · 신규 248 · 교체 26 · 재방문 2 · 철거 1
- **통신방식**: LTE_IV 938 · KS-PLC 776 · K-DCU 525 · LTE 249 · SMGW-C 141 · IoT-PLC 53
- **모뎀 MAC 보유 2,721 / 2,724 (99.9%)** · 고객번호 보유 398 (14.6%)

즉 **대부분이 `구분=기설` 이고 공종이 비어 있다.** 기설은 계기를 새로 갈지 않고 기존 설비에
모뎀만 붙인 행이라 한전 보강현황(계기교체 대장)에 계기가 등장하지 않는다 — 그래서 boranggi
어느 판에도 없다. 고객번호도 대부분 없어 고객번호 축으로도 못 붙는다.
**남은 단서는 모뎀 MAC 뿐이고 그 MAC 이 원장 어디에도 주소를 달고 나타나지 않는다.**
우리 데이터로 더 밀 여지가 없다 — 한전 원천에서 받아야 한다.

**요청 형태 제안**: 이 2,724건은 계기번호보다 **모뎀 MAC 이 유일하게 온전한 키**다(99.9%).
과장에게 "계기번호 목록"이 아니라 **"모뎀 MAC + 계기번호 목록 → 설치 주소"** 로 요청하면
한전 시스템에서 회수될 가능성이 높다.

## 5. ★찾은 함정 두 가지 (다음 사람이 반드시 알아야 한다)

### (1) `ami.db` 의 `계기번호_norm` 열은 접두를 뭉갰다 — 매칭에 쓰지 마라
`boranggi` 47,675건이 `A0530085519` → `00530085519` 로 들어가 있다. `zfill(11)` 을
영문자가 섞인 값에도 적용한 결과다([[meter_no_prefix_preserve]] 가 금지한 바로 그 동작).
**원문 `계기번호` 열에서 다시 정규화**해야 접두 계기가 매칭된다.
이번 산출은 전 구간에서 원문 재정규화로 돌렸고, 원본 대조에서 접두 649건이 그대로 보존됐다.
※ `xlsx_to_db.py` 의 `계기번호_norm` 생성 규칙을 고칠지는 PM 판단 사항으로 남긴다.

### (2) DCU 칸의 순수숫자 10자리는 DCU ID 가 아니라 **LTE 회선번호**다
`dcu_all` 19,007건의 DCU ID 와 변대주번호는 **전수 영문자를 포함**하고 순수숫자는 0건이다.
한전은 LTE 개소의 DCU 칸에 회선번호를 실어 보낸다. 이것을 DCU ID 로 받으면
**앞 8자리 변대주 역산이 통째로 오염된다** — 1차 산출에서 1,854건이 그렇게 들어와
"법칙 위반 792건"으로 잡혔다. 정규화에 `영문자 1자 이상` 조건을 넣고 순수숫자는
`LTE회선번호` 필드로 분리했다(1,981건).
