# 후처리 자동화 기획

> 하루 작업 마감 후, 종로앱에 입력된 데이터를 점검 → 검증 → 수정 → 보고 → 잔해정리까지 자동화.
> 검증 엔진 = ocr-meter (코드는 `research/ocr_poc/`, OCR PM은 ~/Projects/ocr-meter 분리).
> 작성 2026-06-15. 영준님 기획 정리 확정.

## 목적
한전 awms 정산 기준에 우리 데이터(종로 DB)가 정확히 맞도록, 사람 판정은 최소로 두고 앞뒤(수집·검증·반영·보고·정리)를 자동화한다. "LLM 없이 진짜 된다"고 판단되면 그때 툴로 굳힌다 (그 전까지 며칠은 사람+LLM 병행하며 신뢰도 확인).

## 점검 대상 (3가지)
1. 철거 계기번호 정확성
2. 신설 계기번호 정확성
3. 검침값(작업자 입력) 정확성

## 처리 캐스케이드 (깔때기 — 위에서 거르고, 못 거르면 아래로)

```
1단계 [시스템 규칙]   형식부터 거름 — 말도 안 되는 값 즉시 차단
                     예: 계기번호 타입코드 이상(#76 = 51379112262 타입37 존재X),
                         자릿수 위반(검침값 정수부 3~6 벗어남), 0값, 4필드 패턴 위반
        ↓ 통과한 것
2단계 [ocr-meter]    사진 OCR로 입력값 검증
                     · 검침값: PARSeq(cycle6, 90.88%) 사진판독 vs 작업자값, 신뢰도>=0.9
                     · 계기번호: Apple Vision + EasyOCR vs DB값
        ↓ 확신 못 하는 것 (불일치 / 신뢰도 미달 / 2필드+ 누락)
3단계 [need_human]   사람(영준님)이 사진 보고 판정 (verdict: value/reason/custom)
        ↓ 판정 결과
4단계 [처리]         · 틀림      → 수정 (종로DB + awms)
                     · 수정 불가 → 보고
                     · 디스플레이 못 읽음 → 엑셀 보고
```

## 출력 (자동 보고서)
- 수정 완료 건
- 수정 불가 → 보고
- 디스플레이오류(검침값 판독 불가) → 엑셀 (오늘 18 조회불가 / 64·73 디스플레이오류 형태)
- awms 조회 실패 / 등록 실패 → 보고

## 현재 보유 자산 (이미 됨)
- 수집·검진 = `daily_cycle.py` (종로DB+사진 → 검침값/계기번호 대조 → daily_state.csv / daily_meterid.csv, auto/need_human/sonnet/no_crop 분류). 오늘 실측 동작.
- 거르는 규칙 = `engine_compare_common.py`(자릿수 3~6, 정규화, 소수점 버림), `cycle.py`(신뢰도 게이팅 min_conf>=0.9)
- 판정 결과 포맷 = daily_val.json / daily_meterid.json (cands + verdict)
- awms 검침값 수정 API = mobMtr5000/saveRow (EX_WORK_STEP=28, RE_SAVE_YN=Y) — awms_edit_reading_api 메모리
- 계기번호 타입코드 검증 = 종로앱 교체모달 QR (jongno_remark_excel)

## 빠진 것 = 자동화 핵심 (`--apply`)
판정(verdict) → 데이터 반영 단계가 수동. 이걸 자동화해야 함.
- 종로DB patch: removal_values 해당 필드를 verdict로 (Firebase REST)
- awms patch: awms_synced=True(28완료)인 건은 mobMtr5000/saveRow도
- reason(디스플레이오류)은 검침값 비우고 사유 기록

### 안전조건 (2026-06-15 swap 사고에서 배움 — 필수)
daily_val.json이 swap 전 스냅샷이라 verdict가 꼬여 하마터면 오반영할 뻔.
- **live DB 재조회 후, 현재값 != verdict 인 것만** 건드림 (이미 맞은 건 자동 skip = 멱등)
- 적용 전 **parseq(사진판독) <-> verdict 일치 확인**. 어긋나면 자동반영 금지, 사람 재확인 큐로
- 변경 **로그** 남김 (롤백 가능)
- awms 쓰기는 비가역 → 처음엔 dry-run("이렇게 바꿀게요" 출력) → 영준님 승인 후 실제 쓰기

## [별도 트랙] awms 데이터 위생 — 시스템 측 문제
검침 검증과 성격이 다른 awms 쪽 정리. (통신팀 MOBCST 아니라 계기팀 MOBMTR)

- **임시저장(25) 통제**: 종로앱에서 임시저장 상태 유지해야 함.
  - 제약: awms는 한번 저장(28)되면 **임시저장으로 되돌리는 방법이 없음** (resetRows=25삭제만 가능)
- **계기큐**: 임시저장 건은 큐에 안 담기 (이미 작업 — queue.js `if(rep.draft) continue;`, app.js v0615)
- **awms 리스트 위생**: 매번 getMainList 긁을 때 임시저장 같은 쓰레기값 식별 + 중복 제거
- **조회 실패 / 잔해**: awms 등록 실패 건 보고 + 남은 찌꺼기 정리

## 1단계 규칙필터 명세 (영준님 결정 2026-06-15)

**차단 위치 = 후처리에서만.** 작업자 입력 시점(종로앱)에서 막지 않음 — "우리 법칙 예외가 더 있을 수 있어서" 작업을 막으면 안 됨. 후처리에서 형식 위반을 플래그/보고.

### 철거 계기번호
- **계기 추가(신규 사이트 등록) 시점에만 입력받음** → 일일 후처리 대상 아님, 데이터 추가 단계에서 검증
- 형식: `^[0-9]{11}$` + 타입코드 화이트리스트

### 신설 계기번호 (일일 후처리 검증 대상)
- 출처 = **site-data(-new).json = ami-work 신설계기 마스터** (19,613건 = Firebase siteData = stats 분모). 계기번호=신설번호, 계기타입_전=철거된 옛 타입.
- 형식 (전수): 숫자 11자리 18,194(92.8%) / **A 접두 1,188** / **L 접두 231**
- 타입코드(순수숫자11 기준): 53(Amigo)10,924 / 19(EA)5,432 / 55(Amigo)906 / 45(G)886 / 46·47·25·26·27
- **신설 = EA·G·Amigo만** (영준님 확정). A/L 접두 계기는 타입코드 자리가 밀려 50·30·01로 보이는 착시 — 정규화 필요

### 검침값 (일일 후처리 검증 대상)
- normalize(소수점절단+선두0제거) → 정수부 3~6자리
- 자릿수: 단상5 / 삼상6 / 최대전력7(소수)
- 빈값·0 skip, 날짜패턴(20260615)=크롭불량, 4필드(주간/야간/최대=정수, 무효=소수2)
- 최대↔무효 칸 뒤바뀜 검출(자릿수)

### 타입코드 화이트리스트 (영준님 확정)
- **신설**: EA(19) / G(25·26·27·45·46·47) / Amigo(53·55) — 이 셋만
- **철거**: 여러 타입 허용, 회사코드 무시·타입코드 중점. 실측 계기타입_전 = E(17) 14,279 / G 2,199 / **표준형 12** / 미상 3,123
  - **표준형 = 타입코드 15·35** (종로 철거 실측 각 2건). 화이트리스트 밖이라고 무조건 차단 금지(정상건 오차단)
- A/L 접두 신설계기는 타입코드 추출 전 알파벳 정규화 필요

### 데이터 리스트 정체 (헷갈리지 말 것)
- `site-data(-new).json` = ami-work 신설계기 마스터 (신설번호 + 철거전타입). 본체. 19,613.
- `work-status-new.json` = 주소별 작업상태(complete 등). 신설번호 없음.
- `jongno-workStatus-*.json` = 종로 동행시공 백업. 별개 사업(ami-work data 폴더에 섞여 있을 뿐).

### 재사용 (새 코드 최소)
이미 코드에 다 있음. VALID_METER_CODES(a33_meterid.py:75), normalize_checkval/intpart(engine_compare_common.py, cycle.py, daily_cycle.py — 5파일 중복), 자릿수필터(replacement-modal.js:139-153). → 공통 "규칙 모음 모듈"로 통합만.
