# AMI 조직 배선 설계 — 3팀 + PM + ocr-meter (2026-07-19 확정)

> 영준님 확정 (2026-07-19 대화). 지식재구조화 설계(20260713) 6단계 "서브PM 배선"의 집행안.
> 7/13의 시스템축 7분할을 **실조직축 3팀**으로 재편 — 카드 18장은 그대로 팀 매뉴얼로 사용(충돌 없음).
> 배선 수단 = Orca (워크스페이스 + 상주 세션 + 에이전트 간 소통). 에이전트는 Claude 고정 아님(Codex 등 팀별 적임자 가능).

## 1. 조직도 (확정)

```
영준님(대표)
 └─ ami-work PM  ← 통합 CLAUDE.md·코어 방향·팀 간 조율 (실행자 아님)
     ├─ 통신팀   : 아미큐 · 헬퍼 · 아미맵
     ├─ 계기팀   : 계기큐 · 종로맵 (+snap·명륜·구로금천·OTP수집기)
     ├─ 검증팀   : 검증관리자(워크벤치·전송탭) · 후처리/데일리검진
     └─ ocr-meter : OCR 판독 (독립사무소형 — 이미 근무 중, 변경 없음)
```

분할 근거:
- 실존 조직과 일치: 통신팀=영준님 본업(KDN·단독시공) / 계기팀=B2B 위탁(종로 동행) / 검증팀=데이터회사 본업 씨앗
- awms MOBCST↔MOBMTR 교차호출 405(최다 사고 지점)가 팀 경계와 정확히 일치 → 구조가 사고를 차단
- 데이터 응집: 계기큐↔종로맵 workStatus 직결, 아미큐↔아미맵 siteData 직결
- OTP수집기(A31)는 계기큐 로그인용이라 계기팀 소속 (아미큐/헬퍼는 OTP 내장)

## 2. 소유권 (전결표)

| 소유자 | 대상 |
|---|---|
| **PM** | 루트 CLAUDE.md(인덱스·앱버전표) · L0 공용코어 카드 5장 · HANDOFF(단일권위) · awms 공통(API레퍼런스·inject) · workStatus 스키마 · Firebase 구조/rules · 배포 정책 · 팀 간 전달 조율 · 사업방향 정렬(한전리스크·2027 데이터회사·10팀) |
| **팀** | 자기 시스템 카드(4요소) · 담당 폴더 얇은 CLAUDE.md · `.claude/agent-memory/<팀>/` · 팀 카드 범위 내 코드/운영 전결 |
| **ocr-meter** | OCR 판독·학습·OCR_검증규칙.md 정본 (검증팀은 판정 의문 시 이 정본 먼저 확인) |

## 3. 팀 실체 (직원 1팀 = 3파일, 승인 모델 그대로)

1. `.claude/agents/<팀>.md` — 역할·필독 카드 목록·전결 범위·보고 규칙·메모리 경로
2. `.claude/agent-memory/<팀>/` — 팀 전용 메모리 (PM 메모리 오염 금지)
3. 담당 폴더 얇은 CLAUDE.md — 진입점만 (지식 본문은 옵시디언 카드)

매뉴얼 = 옵시디언 시스템 카드 (팀이 카드 여러 장 관할: 계기팀 = 계기큐 + 종로맵 6장 + ...).

## 4. Orca 배선

- **워크스페이스 추가 생성 없음. 워크트리 금지.** 기존 폴더 컨텍스트 그대로:
  - ami-work 컨텍스트: PM 세션 + 통신팀·검증팀 상주 세션 (터미널 추가, 세션명=팀명)
  - jongno-combined 컨텍스트: 계기팀 상주 세션 (이미 별도 repo — 폴더 이동 없이 부서 개소 가능)
  - ocr-meter 컨텍스트: 기존 그대로
- 팀 정체성 부여: 같은 폴더 공존은 `claude --append-system-prompt "$(cat .claude/agents/<팀>.md)"` (폴더=정체성이 아니라 정의파일=정체성)
- 소환 진입: spawn 스킬에 팀 별칭 추가 (통신/계기/검증)
- 소통: 팀 간 대화 = Orca orchestration 또는 mailbox / 긴 산출물 = `/tmp/relay/` / 보고 = PM 세션에 한 줄
- 규약: 세션 삭제 절대금지(닫기만) · disconnected 배지 무시(`orca terminal list`가 진실)

## 5. 개소 순서 (기존 합의 유지)

1. **검증팀** — 7/20 관문(검증관리자 awms 라이브 게이트) 통과 후 1호 개소. 데일리검진 인수인계(PM 검수 2~3회 후 완전 이관)
2. **계기팀 or 통신팀** — 검증팀 안정화 후. 계기팀은 폴더가 이미 독립(jongno-combined)이라 저위험 파일럿 후보
3. 나머지 순차. 한전포털은 일 생기면 검증팀 산하 or 별도 판단

## 6. 유의 (물리 이동 관련)

- **1단계는 폴더 이동 제로** — 부서화는 정의파일+세션으로만. 물리 추출(검증관리자 → 별도 폴더 등)은 별건: 실측조사 → 영준님 승인 → 집행 (launchd 경로·터널·계기큐 원격로드 URL 함정 있음)
- 계기큐 웹(awms-queue-www)은 폰 APK가 ami-work repo URL에서 원격로드 — 폴더 추출 시 APK 수정 필요. 추출 최후순위 or 폴더 유지
- 루트 CLAUDE.md 슬림화가 팀 컨텍스트 경량화의 전제 (하위 폴더 세션도 상위 CLAUDE.md를 읽으므로)
